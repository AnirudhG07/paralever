paralever

The command line

One file in, and one of four things out: a verdict, a run, a parallelization, or a Lean file that proves the program's parallel reading equals its sequential one. The last is the point of the tool.

A checker that prints race-free is a linter, and you believe it or you do not. A tool that writes a module which Lean then checks is different in kind, because the claim leaves with its proof attached. Name a file and no command and the tool answers the question a file arrives with — is this program race-free, and if so what holds of it.

console 
lake build paralever                      # ./.lake/build/bin/paralever

paralever         Examples/Language/sum.prl    # the verdict, and the evidence for it
paralever check   Examples/Language/sum.prl
paralever prove   Examples/Language/sum.prl -o Proofs/Sum.lean --check
paralever to-mlir Examples/Language/sum.prl -o sum.mlir
paralever to-prl  Examples/Mlir/doall-no.mlir

Both front ends, one program

Every command takes a .prl file or a .mlir module in generic form, because both compile to the same pair — a Layout saying where the buffers are, and an unrolled ParProg.

The commands

CommandWhat it prints
init [DIR]a Lake project with paralever as its dependency: a lakefile.toml, this project's lean-toolchain, a program, and a module whose last line is par_seq_eq
FILE (no command)the verdict, then everything run prints, then the interleaving if there is one

funcs FILEwhat an MLIR module holds, function by function, and whether the reader takes each one
prove FILEa Lean module stating what holds of the program
vc FILEthe independence obligation as SMT-LIB, for a solver to discharge

to-mlir FILEthe program as MLIR generic form

OptionEffect
-o PATHwrite there instead of to standard output
--threadsrun one Task per thread of every fork rather than the canonical order. The heap is the same one, which is what runTask_eq says for every program wfB accepts
--autoparmake prove, to-mlir and to-lean take the parallelized program as their subject

-n NAMErun: that buffer alone, or one cell of it when the name carries a subscript — -n 'C[1, 2]'
--quiet, -qrun and the no-command form: only what the program's print statements wrote — no headings, no heap, no verdict
--verbose, -vverbosity on, which is the default; it undoes an earlier --quiet
--all-cellsrun: every cell of every buffer, instead of the first 32 of each
--colourpaint to-prl's output in the editor grammar's token classes

check and the no-command form exit 1 when the program has a race, so a build can gate on either:

console 
for f in Examples/Language/*.prl; do paralever check "$f" || echo "$f is racy"; done

The report ends with the verdict, and the verdict answers two questions, because a program with a computed address has two different answers. This heap is the one the file's buf initializers describe, and raceSites decides it exactly. Any heap is the universally quantified statement: wfB decides it when it accepts, and when it refuses a bounded search looks for a heap at which two threads collide. The two print as one line when they agree and as two when they differ. 

$ paralever check Examples/Language/stripe.prl
  verdict   this heap   Proved: Yes — no two threads touch one cell here
            any heap    RACE found — with k[1] = -1: A[0] written by both threads

$ paralever check Examples/Language/branch.prl
  verdict   this heap   Proved: Yes — no two threads touch one cell here
            any heap    Inconclusive — wfB refuses over {A[0], A[1]}: a branch contributes both arms although only one runs
            no race found in 11 heap(s) probed over {c[0]}

Proved: Yes is a Lean proof either way — for every heap from wfB, for one heap from raceSites_nil_iff. Inconclusive names both of its reasons: what wfB refused over and which constructor widened the footprint, then how far the search looked. Only a race at the declared heap exits 1, and only a real interleaving earns RACE found there. Nothing is restated after the report and no next command is suggested.

What run prints

Most of what a .prl program says is the heap it leaves, so run prints that heap as the buffers the file declared. A print statement writes a line above it, under its own heading; a program with no print has no such section at all.

console 
$ paralever run Examples/Language/arena.prl
heap after the run — the cells the program left behind, which is most of what it says
12 cells in 3 buffers, 1 of them freed, addressed 0 to 11
NAME [dims] @base — the buffer's first cell in that flat heap; cells row-major from there

src [4] @0  [1, 2, 3, 4]
tmp [4] @4  [3, 5, 7, 9]   (freed)
out [4] @4  [3, 5, 7, 9]

A bare paralever FILE prints this same body under its verdict. Both commands call one function, Tool.runBody, so whatever run says about a program a bare invocation says too, and the verdict is the whole of the difference. Memory, footprint, thread count and rounds belong to check, which is the command for them.

--quiet (-q) turns the verbosity off for either command and prints only what the program's print statements wrote — no headings, no heap, no verdict. A program with no print is then silent rather than printing a blank line, and the exit code is unchanged, so a quiet invocation is still the gate:

console 
$ paralever -q Examples/Language/stripe.prl
k = [0, 1]

[4] is the shape — a [2, 6] buffer prints as two rows — and @4 is the address of the buffer's first cell in the one flat heap that State = Loc → Val gives. tmp and out print the same numbers because free returns the cells and the next buffer is placed on them; the (freed) marker says which of the two is dead. A report is read, not elaborated, so none of it is commented out — the -- prefix is kept for output that is source, where the reader's approximations must survive in a file that still compiles.

One buffer, and all of the cells

A buffer wider than the terminal is not a report. Each one prints at most Lang.runCells = 32 cells, rounded up to a whole row for a matrix, and then says how many it left out — so the shape and the leading values stay legible on a program whose heap is thousands of cells.

console 
$ paralever run Examples/Scale/matmul12.prl
…
C [12, 12] @288  [6072, 6138, 6204, 6270, 6336, 6402, 6468, 6534, 6600, 6666, 6732, 6798]
                 [15576, 15786, 15996, 16206, 16416, 16626, 16836, 17046, 17256, 17466, 17676, 17886]
                 [25080, 25434, 25788, 26142, 26496, 26850, 27204, 27558, 27912, 28266, 28620, 28974]
                 … +9 more rows

Two options say otherwise. --all-cells lifts the limit on every buffer. -n asks for one buffer by name, printed in full and with nothing around it, and a subscript asks for the single cell:

console 
$ paralever run Examples/Language/matmul.prl -n C
C [2, 2] @8  [19, 22]
             [43, 50]

$ paralever run Examples/Language/matmul.prl -n 'C[1, 1]'
C[1, 1] @11  50

The address comes with the value because the cell is one of State = Loc → Val's, and @11 is where Layout.at "C" [1, 1] sends that subscript. A name no buffer has, or a subscript outside the shape, is an error naming what the program does declare, and exits 2 rather than printing a default. When the program has a race, -n's caveat goes to standard error, so the one line on standard output stays greppable.

What prove writes

Three cases, and no choice about which one applies. The program decides, by which check it passes.

The programThe theoremHow
wfB = true ParSeqEq at every heap and register file ParProg.par_seq_eq (by decide) ρ σ
wfB = false, but the exact check accepts at the declared heap ParSeqEq at that heap parSeqEq_of_runSeq_eq from the exact check
both refuse no theorem; both refusals, proved by decide on each

The first case, which is what the library is for

wfB decides Bernstein's condition at every par node by reading the syntax, so it holds at every heap — and that is exactly par_seq_eq's hypothesis.

Lean 4 · written by paralever prove

The second case: a computed address

dst[%i] has a footprint of all of dst, because the index is not known from the syntax, so two threads that write distinct cells still look like they collide and wfB refuses. The per-heap check measures the accesses along the canonical run instead, and accepts — which buys the equivalence at the heap the file declares, and nowhere else.

Lean 4 · written by paralever prove

The third case: a real race

The generated file says so and proves both refusals. No theorem of this shape exists for such a program: its parallel reading reaches wrong, which is no terminating outcome, while its sequential reading terminates. paralever race FILE prints the interleaving that does it.

A fourth, when the file states a claim

An assert adds a section to whichever of the three the left program earned, so a claim file's module states both: the main theorem for the left program, and AgreeOn for the pair. Here is the module for equiv.prl, which compares bubble sort against odd-even transposition sort.

Lean 4 · written by paralever prove

Three decides and the claim holds: the check on each side, and one run of each sequential reading compared at the cells on named. check reports the same answer beside the verdict and exits non-zero when it fails.

console 
$ paralever check Examples/Language/equiv.prl
Examples/Language/equiv.prl
  memory    A[8] @0  (8 cells)
  reads     {A[0], A[1], A[2], A[3], A[4], A[5], A[6], A[7]}
  writes    {A[0], A[1], A[2], A[3], A[4], A[5], A[6], A[7]}
  threads   1
  rounds    224 parallel, 224 sequential
  verdict   every heap  Proved: Yes — wfB accepts: the threads' footprints are pairwise independent
  claim     bubble == oddeven on A
            Agree: Yes — the same 8 cell(s), under every schedule of either side

Three details of the generated module. It reads the source through prl_file or mlir_prog, which compile the file while the module elaborates, so by decide sees a program literal and never runs the reader. The path it names is relative to the module's own directory when the two live in one tree, and absolute otherwise. And --check shells out to lake env lean, so the tool reports Lean's verdict rather than its own.

What vc hands to a solver

A computed address makes the footprint read off the syntax every cell of its buffer, so wfB declines programs whose threads provably touch different cells. vc states the same Bernstein condition over the index expressions instead. Registers are substituted away first, so an index that folds to a literal is decided in Lean and never reaches a solver; what is left is one (check-sat) per parallel block, unsatisfiable exactly when that block is independent.

the answerwhat it is worth
unsatdischarged by the named solver, not by Lean's kernel. An external refutation is not a checked proof, so the report says which solver and which version said so. prove stays the only path that ends in a proof.
sata claim about two cells, recomputed in Lean before it is believed. But an assignment is not a run, so this is the obligation failing — reported as inconclusive, never as RACY. Only a real interleaving earns that word.
neitherthe solver ran out of time — --timeout MS is the knob, 10000 by default — or none is installed. No solver is a build dependency, and lake build is green without one.

The gain is one file wide. Examples/Language/stripe.prl has two threads writing the even and the odd cells of one buffer, with both indices loaded from memory: 

$ paralever Examples/Language/stripe.prl
Examples/Language/stripe.prl
  verdict   this heap   Proved: Yes — no two threads touch one cell here
            any heap    RACE found — with k[1] = -1: A[0] written by both threads
...

$ paralever vc Examples/Language/stripe.prl --solve --assume nonneg
assuming nonneg
this heap   Proved: Yes — no two threads touch one cell here
any heap    RACE found — with k[1] = -1: A[0] written by both threads
solver: Z3 version 5.3.1 - 64 bit — unsat is its word, not Lean's
fork 0 — 2 threads
  3 pair(s) left to decide, over 2 unknown value(s), in QF_LIA
  u0  the value read from k[0]
  u1  the value read from k[1]
  independent — unsat

Each unknown is named by the cell it was read from, because an obligation nobody can read is an obligation nobody can add a hypothesis to. --assume nonneg is that hypothesis in the one case it is always wanted: ArrRef.addr clamps a negative index to its buffer's first cell, so without it every thread with a possibly-negative computed index aliases there — and a solver reports that collision in preference to any other, correctly. The assumption weakens the claim, so the report names it on its first line — and the any heap verdict above it is Lean having found the same collision without a solver, at k[1] = -1.

The four reports, also inside Lean

The executable is a thin wrapper. The same four views are #evals over a program read at elaboration time, so a file can be the subject of a theorem without a build step in between.

ViewWhat it prints
checkReportdeclared memory, footprint by name, thread count, rounds, verdict
runReportthe buffers after a run, sequential or on real threads
raceReportthe interleaving that realizes a race, replayed against step
parReportthe rewrite's output as .prl, with the plan's numbers
paralever run Examples/Language/sum.prl 
A [6] @0  [1, 2, 3, 4, 5, 6]
out [3] @6  [3, 7, 11]

With --threads the same program runs one Task per thread of every fork, and prints the same table. That is not luck: runTask_eq proves the threaded run leaves the heap the canonical order leaves, for every program wfB accepts.

The two conversions

to-prl on a .mlir file and to-mlir on a .prl file are the same program printed by the other front end's printer, with the reader's approximations as comments at the top. Here is doall-no.mlir coming back as .prl, its affine.parallel unrolled into eight threads:

paralever to-prl Examples/Mlir/doall-no.mlir 
buf A[8] = 1, 2, 3, 4, 5, 6, 7, 8
buf B[8] = 10, 20, 30, 40, 50, 60, 70, 80
buf C[8]

parallel {
  %0 := A[0]
  %1 := B[0]
  C[0] := (%0 + %1)
} | {
  %0 := A[1]
  %1 := B[1]
  C[1] := (%0 + %1)
} | {
  …six more threads…
}

A full cycle changes one thing: MLIR globals must carry an initial value, so a buffer the .prl file left implicit comes back as buf out[4] = 0, 0, 0, 0.

What to-mlir cannot do is refuse quietly. Three programs have no generic form in the supported operation set, and each gets a named error: a file with a conditional or a loop, a computed subscript into a multi-dimensional buffer, and a layout where a free returned space so two buffers share cells — two MLIR globals cannot alias.

Limits

  • ▸

    prove writes; Lean checks. Without --check the tool does not run Lean, so a module it writes for a large program can still be slow to check or exceed the recursion bound — decide reduces the program against a heap. The generated module raises the bound and says why.

  • ▸

    --check needs the repository. It shells out to lake env lean, so it has to run from a directory where lake resolves this package.

  • ▸

    One function per module. An MLIR file with several functions and none called main is refused rather than guessed at, because interprocedural calls are not supported.

  • ▸

    The subject is the whole program. There is no option to name an entry region; a labelled region is reachable from Lean with ParProg.findLabel.

  • ▸

    Registers come back renumbered through MLIR. SSA values are not assignable, so a register assignment with no memory in it is inlined into whatever reads it. The program's memory, footprint, verdict and heap are unchanged, which is what the round-trip gate compares.
