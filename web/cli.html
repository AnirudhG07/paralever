paralever

The command line

One file in, and one of four things out: a verdict, a run, a parallelization, or a Lean file that proves the program's parallel reading equals its sequential one. The last is the point of the tool.

A checker that prints race-free is a linter, and you believe it or you do not. A tool that writes a module Lean then checks is different in kind: the claim leaves with its proof attached. Name a file and no command, and the tool answers the question a file arrives with.

console 
lake build paralever                      # ./.lake/build/bin/paralever

paralever         Examples/Language/sum.prl    # the verdict, and the evidence for it
paralever check   Examples/Language/sum.prl
paralever prove   Examples/Language/sum.prl -o Proofs/Sum.lean --check
paralever to-mlir Examples/Language/sum.prl -o sum.mlir
paralever to-prl  Examples/Mlir/doall-no.mlir

Both front ends, one program

Every command takes a .prl file or an .mlir module. Both compile to the same pair: a layout saying where the buffers are, and an unrolled program.

The commands

CommandWhat it prints
init [DIR]a Lake project with paralever as its dependency: a lakefile.toml, this project's lean-toolchain, a program, and a module whose last line is par_seq_eq
FILE (no command)the verdict, then everything run prints, then the interleaving if there is one
check FILEmemory, reads, writes, thread count, rounds, verdict
run FILE [-n NAME]the heap after a run, buffer by buffer, or one buffer of it
race FILEthe interleaving that reaches wrong, step by step
autopar FILEthe parallelized program as .prl, with the plan's numbers
funcs FILEwhat an MLIR module holds, function by function, and whether the reader takes each one
prove FILEa Lean module stating what holds of the program
vc FILEthe independence obligation as SMT-LIB, for a solver to discharge
to-prl FILEthe program as .prl
to-mlir FILEthe program as MLIR generic form
to-lean FILEa Layout and a paralever { … } block
OptionEffect
-o PATHwrite there instead of to standard output
--threadsrun one Task per thread of every fork rather than the canonical order. The heap is the same one, which is what runTask_eq says for every program wfB accepts
--autoparmake prove, to-mlir and to-lean take the parallelized program as their subject
--checkrun lake env lean on what prove wrote, and report Lean's verdict rather than the tool's
--solvevc: discharge what is left with the first solver found: z3, then cvc5, or whatever PARALEVER_SMT names
--solver NAME|PATHvc: use that solver rather than looking for one; implies --solve
--timeout MSvc: milliseconds per query, 10000 by default, 0 for no limit
--assume nonnegvc: assume every value read from the heap is at or above zero, which the clamp in ArrRef.addr makes necessary more often than it looks
--prove PATHno command: write the Lean module that proves the verdict to PATH as well as printing the verdict itself
--func NAMEthe function to read, in an MLIR module that holds several. In custom form it reads that function alone, so a reduction in the next one does not refuse the file
-n NAMErun: that buffer alone, or one cell of it when the name carries a subscript, as in -n 'C[1, 2]'
--quiet, -qrun and the no-command form: only what the program's print statements wrote, with no headings, no heap and no verdict
--verbose, -vverbosity on, which is the default; it undoes an earlier --quiet
--all-cellsrun: every cell of every buffer, instead of the first 32 of each
--colourpaint to-prl's output in the editor grammar's token classes

check and the no-command form exit 1 when the program has a race, so a build can gate on either:

console 
for f in Examples/Language/*.prl; do paralever check "$f" || echo "$f is racy"; done

The report ends with the verdict, and the verdict answers two questions. This heap is the one the file's initializers describe, and the exact scan decides it. Any heap is the universally quantified claim: the syntactic check decides it when it accepts, and when it refuses, a bounded search looks for a heap where two threads collide. The two print as one line when they agree and as two when they differ. 

$ paralever check Examples/Language/stripe.prl
  verdict   this heap   Proved: Yes — no two threads touch one cell here
            any heap    RACE found — with k[1] = -1: A[0] written by both threads

$ paralever check Examples/Language/branch.prl
  verdict   this heap   Proved: Yes — no two threads touch one cell here
            any heap    Inconclusive — wfB refuses over {A[0], A[1]}: a branch contributes both arms although only one runs
            no race found in 11 heap(s) probed over {c[0]}

Proved: Yes is a Lean proof either way. An Inconclusive names both its reasons: what the check refused over, which constructor widened the footprint, and how far the search looked. Only a race at the declared heap exits 1, and only a real interleaving earns RACE found.

What run prints

Most of what a program says is the heap it leaves, so run prints that heap as the buffers the file declared. A print statement writes a line above it, under its own heading. A program with no print has no such section.

console 
$ paralever run Examples/Language/arena.prl
heap after the run — the cells the program left behind, which is most of what it says
12 cells in 3 buffers, 1 of them freed, addressed 0 to 11
NAME [dims] @base — the buffer's first cell in that flat heap; cells row-major from there

src [4] @0  [1, 2, 3, 4]
tmp [4] @4  [3, 5, 7, 9]   (freed)
out [4] @4  [3, 5, 7, 9]

A bare paralever FILE prints the same body under its verdict. Both commands call one function, so the verdict is the whole of the difference. Memory, footprint, thread count and rounds belong to check.

-q prints only what the program's print statements wrote: no headings, no heap, no verdict. A program with no print is then silent rather than blank. The exit code is unchanged, so a quiet invocation is still a gate.

console 
$ paralever -q Examples/Language/stripe.prl
k = [0, 1]

[4] is the shape, and a two-dimensional buffer prints as rows. @4 is the address of its first cell in the one flat heap. Two buffers print the same numbers when free returned the cells and the next buffer was placed on them, and the (freed) marker says which one is dead. A report is read, not elaborated, so none of it is commented out.

One buffer, and all of the cells

A buffer wider than the terminal is not a report. Each prints at most 32 cells, rounded up to a whole row for a matrix, then says how many it left out. The shape and the leading values stay legible on a heap of thousands of cells.

console 
$ paralever run Examples/Scale/matmul12.prl
…
C [12, 12] @288  [6072, 6138, 6204, 6270, 6336, 6402, 6468, 6534, 6600, 6666, 6732, 6798]
                 [15576, 15786, 15996, 16206, 16416, 16626, 16836, 17046, 17256, 17466, 17676, 17886]
                 [25080, 25434, 25788, 26142, 26496, 26850, 27204, 27558, 27912, 28266, 28620, 28974]
                 … +9 more rows

Two options say otherwise. --all-cells lifts the limit everywhere. -n asks for one buffer by name, printed in full with nothing around it, and a subscript asks for one cell.

console 
$ paralever run Examples/Language/matmul.prl -n C
C [2, 2] @8  [19, 22]
             [43, 50]

$ paralever run Examples/Language/matmul.prl -n 'C[1, 1]'
C[1, 1] @11  50

The address comes with the value, because @11 is where that subscript lands in the flat heap. A name no buffer has, or a subscript outside the shape, is an error naming what the program does declare, and exits 2. When the program has a race, the caveat goes to standard error, so the one line on standard output stays greppable.

What prove writes

Three cases, and no choice about which one applies. The program decides, by which check it passes.

The programThe theoremHow
wfB = true ParSeqEq at every heap and register file ParProg.par_seq_eq (by decide) ρ σ
wfB = false, but the exact check accepts at the declared heap ParSeqEq at that heap parSeqEq_of_runSeq_eq from the exact check
both refuse no theorem; both refusals, proved by decide on each

The first case, which is what the library is for

wfB decides Bernstein's condition at every par node by reading the syntax, so it holds at every heap, which is exactly par_seq_eq's hypothesis.

Lean 4 · written by paralever prove

The second case: a computed address

A computed index has a footprint of the whole buffer, because the index is not known from the syntax. Two threads writing distinct cells still look like they collide, so the syntactic check refuses. The per-heap check measures the accesses along the canonical run instead, and accepts. That buys the equivalence at the declared heap and nowhere else.

Lean 4 · written by paralever prove

The third case: a real race

The generated file says so and proves both refusals. No theorem of this shape exists for such a program. Its parallel reading reaches wrong while its sequential reading terminates. paralever race FILE prints the interleaving that does it.

A fourth, when the file states a claim

An assert adds a section to whichever of the three the left program earned. A claim file's module then states both: the main theorem for the left program, and the agreement for the pair. Here is equiv.prl, which compares bubble sort against odd-even transposition sort.

Lean 4 · written by paralever prove

Three decisions and the claim holds: the check on each side, and one run of each sequential reading compared at the named cells. check reports the same answer beside the verdict.

console 
$ paralever check Examples/Language/equiv.prl
Examples/Language/equiv.prl
  memory    A[8] @0  (8 cells)
  reads     {A[0], A[1], A[2], A[3], A[4], A[5], A[6], A[7]}
  writes    {A[0], A[1], A[2], A[3], A[4], A[5], A[6], A[7]}
  threads   1
  rounds    224 parallel, 224 sequential
  verdict   every heap  Proved: Yes — wfB accepts: the threads' footprints are pairwise independent
  claim     bubble == oddeven on A
            Agree: Yes — the same 8 cell(s), under every schedule of either side

Three details of the generated module. It reads the source while the module elaborates, so by decide sees a program literal and never runs the reader. The path it names is relative when the two live in one tree, and absolute otherwise. --check shells out to Lean, so the tool reports Lean's verdict rather than its own.

Full detail: docs/cli.md.

What vc hands to a solver

A computed address widens the footprint to the whole buffer, so the syntactic check declines programs whose threads provably touch different cells. vc states the same Bernstein condition over the index expressions instead. Registers are substituted away first, so an index that folds to a literal is decided in Lean and never reaches a solver. What is left is one query per fork, unsatisfiable exactly when that fork is independent.

the answerwhat it is worth
unsatDischarged by the named solver rather than by Lean's kernel. An external refutation is not a checked proof, so the report says which solver and which version said so. prove stays the only path that ends in a proof.
sata claim about two cells, recomputed in Lean before it is believed. An assignment is not a run, so this is the obligation failing, reported as inconclusive rather than as RACY. Only a real interleaving earns that word.
neitherthe solver ran out of time (--timeout MS is the knob, 10000 by default), or none is installed. No solver is a build dependency, and lake build is green without one.

The gain is one file wide. Examples/Language/stripe.prl has two threads writing the even and the odd cells of one buffer, with both indices loaded from memory: 

$ paralever Examples/Language/stripe.prl
Examples/Language/stripe.prl
  verdict   this heap   Proved: Yes — no two threads touch one cell here
            any heap    RACE found — with k[1] = -1: A[0] written by both threads
...

$ paralever vc Examples/Language/stripe.prl --solve --assume nonneg
assuming nonneg
this heap   Proved: Yes — no two threads touch one cell here
any heap    RACE found — with k[1] = -1: A[0] written by both threads
solver: Z3 version 5.3.1 - 64 bit — unsat is its word, not Lean's
fork 0 — 2 threads
  3 pair(s) left to decide, over 2 unknown value(s), in QF_LIA
  u0  the value read from k[0]
  u1  the value read from k[1]
  independent — unsat

Each unknown is named by the cell it was read from. An obligation nobody can read is one nobody can add a hypothesis to. --assume nonneg is that hypothesis in the case it is always wanted. A negative index is clamped to the buffer's first cell, so without the assumption every possibly-negative index aliases there, and a solver correctly reports that collision ahead of any other. The assumption weakens the claim, so the report names it on its first line.

Full detail: docs/smt-vc.md.

The four reports, also inside Lean

The executable is a thin wrapper. The same four views are #evals over a program read while Lean elaborates, so a file can be the subject of a theorem with no build step between.

ViewWhat it prints
checkReportdeclared memory, footprint by name, thread count, rounds, verdict
runReportthe buffers after a run, sequential or on real threads
raceReportthe interleaving that realizes a race, replayed against step
parReportthe rewrite's output as .prl, with the plan's numbers
paralever run Examples/Language/sum.prl 
A [6] @0  [1, 2, 3, 4, 5, 6]
out [3] @6  [3, 7, 11]

With --threads the same program runs one real thread per child of every fork, and prints the same table. That is not luck. A theorem says the threaded run leaves the heap the canonical order leaves, for every accepted program.

The two conversions

Each conversion is the same program printed by the other front end's printer, with the reader's approximations as comments at the top. Here is doall-no.mlir coming back as .prl, its parallel loop unrolled into eight threads.

paralever to-prl Examples/Mlir/doall-no.mlir 
buf A[8] = 1, 2, 3, 4, 5, 6, 7, 8
buf B[8] = 10, 20, 30, 40, 50, 60, 70, 80
buf C[8]

parallel {
  %0 := A[0]
  %1 := B[0]
  C[0] := (%0 + %1)
} | {
  %0 := A[1]
  %1 := B[1]
  C[1] := (%0 + %1)
} | {
  …six more threads…
}

A full cycle changes one thing. MLIR globals must carry an initial value, so a buffer the file left implicit comes back written out.

What to-mlir cannot do is refuse quietly. Three kinds of program have no generic form here, and each gets a named error: a file with a conditional or a loop, a computed subscript into a multi-dimensional buffer, and a layout where two buffers share cells after a free.

Limits

  • ▸

    prove writes and Lean checks. Without --check the tool does not run Lean, so a module for a large program can still be slow or exceed the recursion bound. The generated module raises that bound and says why.

  • ▸

    --check needs the repository. It shells out to lake env lean, so it has to run from a directory where lake resolves this package.

  • ▸

    One function per module. An MLIR file with several functions and none called main is refused rather than guessed at, because interprocedural calls are not supported.

  • ▸

    The subject is the whole program. There is no option to name an entry region; a labelled region is reachable from Lean with ParProg.findLabel.

  • ▸

    Registers come back renumbered through MLIR. SSA values are not assignable, so a register assignment with no memory in it is inlined into whatever reads it. The memory, footprint, verdict and heap are unchanged, and that is what the round-trip gate compares.
