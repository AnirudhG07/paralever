Autoparallelization

The common case is a program nobody parallelized. An untrusted analysis proposes a tree of forks; a proved gate decides whether to take it. The resulting theorem has no hypothesis, because the pass returns the program unchanged when its own check fails.

The theorem

Lean 4 · Paralever/AutoPar/Rewrite.lean

No hypothesis. For every program p, the rewritten program read in parallel leaves exactly the heap the original leaves read sequentially. That is possible only because rewrite checks its own plan and returns p untouched when the check fails: the analysis is untrusted and the gate is proved, which is the same architecture as the race search.

The equation is about the heap, not the pair. At a fork, execPar hands the continuation the pre-fork register file, so there is nothing to say about registers afterwards.

rewrite_sound is about one schedule, the reference one. A companion lemma, rewrite_wf, carries wfB through the rewrite and feeds par_seq_eq, so rewrite_parSeqEq gives every schedule.

One file, start to finish

chain.prl is two independent squaring computations written interleaved, then a join that reads both. Nothing in it is marked parallel.

-- committed true, optimal true

Ten statements became five scheduling units in three stages. The depth fell from 9 memory operations to 6, and optimal true is not an estimate: 6 is the critical path of the dependence DAG, and no schedule of those units — fork–join or otherwise — can do better.

The pass, in four steps

1

flatten — the ;-chain as a list

A parallel block counts as one statement; the pass does not descend into it.

2

atoms — regroup into register-closed segments

A boundary may be placed after a prefix only when no register that prefix writes is still live in what follows. Liveness kills on must-writes, not may-writes: a conditional's write set is the union of its branches and only one branch runs, so killing on the union would under-approximate what is live, which is unsound. Without the kill, a reused %0 would look live across the whole program and no boundary would ever be legal.

3

plan — one left-to-right fold

Greedy prefix grouping, the obvious alternative, gets a depth of 5 on the two-interleaved-chains example where this gets 3, because one conflicting unit ends its group even when everything after it is free.

4

emit — stages to par nodes

A singleton thread stays a plain statement rather than becoming a one-thread fork.

Order preservation is the load-bearing restriction.

A plan is a two-level consecutive partition, which makes planUnits (plan us) = us a structural theorem rather than a run-time check, and means the soundness proof needs only par_block_heap. A scheduler that reordered units would need a commutation theorem — independent statements may be transposed — and that is not proved here.

The bound is a certificate, not an estimate

The dependence DAG is built in one scoreboard pass, because Bernstein's three clauses are the three kinds of edge.

critical is that DAG's longest path, and it is a lower bound on the depth of any schedule of those units. So optimalB p, which is depth (rewrite p) == critical (units p), certifies optimality rather than guessing at it. Each kind of edge is pinned by one test:

Cost is depth, counted off the syntax: + at a seq, foldr max at a par, memory operations only. The library's real cost model needs a heap and is quadratic in the work to evaluate, which a scheduling heuristic cannot afford.

How the proof goes

Step 2 is the idea. Because a fork restores the register file, a chain of forks never advances it, so the whole top-level plan sits in exactly the position fork_heap was written for — one level up from a single par. Steps 4 and 5 are the bookkeeping that makes that identification legitimate.

What the gate still refuses

rewriteOk requires that no thread read a register an earlier thread writes, tested on raw read sets. That is stronger than the liveness atoms actually establishes: a segment that writes %0 and then reads it has %0 in its raw read set even though the value is local to the segment. So a chain that reuses %0 across segments is declined and returned sequential.

prl 
[10] := 1; [11] := 2; %0 := [10]; [12] := %0; %0 := [11]; [13] := %0

Sound, and the parallelism is lost. There are two ways out, in order of value. Make registers survive the join: execPar's par case discards the children's register files, and merging them instead — guarded by register-Bernstein among siblings — removes the constraint at its source. Registers can be renamed per thread at emission where memory cells cannot, because a location is reached by a computed address, so the cell is the name. Or weaken the gate to liveness, which means restating the agreement lemma over a statement list.

Also refused, by construction rather than by the gate: anything the footprint over-approximates. A[B[i]] reports the whole array, so scatters serialise, and whileAtMost is nested conditionals whose footprint is the branch union, so iterations look dependent. Conservative, never unsound.

Two routes to a forked program

Both are live, and neither is a superset of the other.

ParProg.autoParAutoPar.rewrite
What is provedNothing in general. wfB is decided on the result, per programrewrite_sound, for every program, no hypothesis
Groupinggreedy: the longest independent prefixthe three-case fold, with a critical-path certificate
Register handlingliveness, via atomsliveness for the cut, raw read sets for the gate — so stricter
Refuseslessmore, including chains the other forks

The first route's claim is per program and checked by decide; the second's is a theorem. A chain that reuses %0 across segments forks under the first and is returned unchanged by the second — which is the measured price of having the proof.
