Autoparallelization

The common case is a program nobody parallelized. An untrusted analysis proposes a tree of forks, and a proved gate decides whether to take it. The theorem that comes out has no hypothesis at all.

The theorem

Lean 4 · Paralever/AutoPar/Rewrite.lean

There is no hypothesis. For every program, the rewritten version read in parallel leaves exactly the heap the original leaves read sequentially. That works because the pass checks its own plan and returns the program untouched when the check fails. The analysis is untrusted and the gate is proved, which is the same shape as the race search.

The equation is about the heap, not the pair. A fork hands the continuation the register file as it stood before, so there is nothing to say about registers afterwards.

That lemma is about one schedule, the reference one. A companion carries the independence check through the rewrite and feeds the main theorem, which gives every schedule.

One file, start to finish

-- committed true, optimal true

Nine statements became five scheduling units in three stages. Depth fell from 9 memory operations to 6. optimal true is a certificate, not an estimate: 6 is the critical path of the dependence graph, so no schedule of those units can do better.

The pass, in four steps

1

flatten: the ;-chain as a list

A parallel block counts as one statement; the pass does not descend into it.

2

atoms: regroup into register-closed segments

A boundary is legal after a prefix only when no register that prefix writes is still live below it. Liveness kills on must-writes, never on may-writes: only one branch of a conditional runs, so killing on the union would be unsound. Without the kill, a reused register would look live everywhere and no boundary would ever be legal.

3

plan: one left-to-right fold

Greedy prefix grouping is the obvious alternative. It gets depth 5 on this example where the fold gets 3, because one conflicting unit ends its group even when everything after it is free.

4

emit: stages to par nodes

A singleton thread stays a plain statement rather than becoming a one-thread fork.

Order preservation is the load-bearing restriction.

A plan is a two-level consecutive partition. Recovering the original unit list from a plan is therefore a structural theorem, not a run-time check. A scheduler that reordered units would need a commutation theorem saying independent statements may be transposed, and that is not proved here.

The critical-path certificate

The dependence DAG is built in one scoreboard pass, because Bernstein's three clauses are the three kinds of edge.

The critical path is that graph's longest path, and it is a lower bound on the depth of any schedule of those units. So comparing the plan's depth against it certifies optimality rather than guessing at it. Each kind of edge is pinned by one test.

Depth is counted off the syntax: add along a chain, take the maximum across a fork, count memory operations only. The library's full cost model needs a heap and is quadratic to evaluate, which a scheduling heuristic cannot afford.

How the proof goes

Step 2 is the idea. A fork restores the register file, so a chain of forks never advances it. The whole top-level plan therefore sits in exactly the position the fork lemma was written for, one level up. Steps 4 and 5 are the bookkeeping that makes that legitimate.

What the gate still refuses

The gate asks that no thread read a register an earlier thread writes, tested on raw read sets. That is stronger than the liveness the pass actually establishes. A segment that writes a register and then reads it still has that register in its raw read set, even though the value never leaves the segment. So a chain that reuses one register across segments is declined and returned sequential.

prl 
[10] := 1; [11] := 2; %0 := [10]; [12] := %0; %0 := [11]; [13] := %0

The refusal is sound, and the parallelism is lost. Two ways out, in order of value. The first is to let registers survive the join: a fork currently discards the children's register files, and merging them instead removes the constraint at its source. Registers can be renamed per thread, where memory cells cannot. The second is to weaken the gate to liveness, which means restating the agreement lemma over a statement list.

One more thing is refused, by construction rather than by the gate: anything the footprint over-approximates. A computed index reports the whole array, so scatters serialise. A bounded loop is nested conditionals, so its iterations look dependent. That is conservative and never unsound.

Full detail: docs/autopar.md.

Two routes to a forked program

Both are live, and neither is a superset of the other.

The first route's claim is per program and checked by decide; the second's is a theorem. A chain that reuses %0 across segments forks under the first and is returned unchanged by the second, which is the measured price of having the proof.
