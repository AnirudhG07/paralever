From MLIR

Hand-translating a benchmark is the dominant threat to validity for any claim measured on one, because the translation is part of what is being measured and is itself unverified. Reading MLIR removes that threat by making the translation mechanical and auditable.

Two stages, and only the second is ours

Generic form, not each dialect's own assembly. --mlir-print-op-generic prints every operation the same way, so one reader covers affine, memref, arith and func. The custom form (affine.for %i = 0 to 8 { … }) needs a parser per dialect, which is what would make "one converter" false. Affine maps are the only piece with their own grammar.

Not LLVM IR. It sits below the level that can be consumed here, for two independent reasons.

LLVM IRMLIR affine/scf/memref
Control flowunstructured br, phi nodesstructured regions
Representable in ParM?no — ParM is inductive, so arbitrary jumps have no encoding at allyes
Affine mapsgone; a loop is a CFGpresent, and they are what is needed

So consuming LLVM IR would mean writing a loop structurizer first, and going through one destroys the information the lowering depends on.

An affine map is a footprint function

This is the alignment the design rests on. The N-ary fork lemma asks for each thread's read and write sets as two lists of locations. An affine.store already carries exactly that:

mlir 
"affine.store"(%v, %A, %i, %j) {map = affine_map<(d0, d1) -> (d0, d1)>}

The map is evaluated at each point of the index box, so the footprint stays exact — a literal location per access, not a bound on an array. That is what keeps wfB able to accept the program at all. A memref.load with a computed index gets the data-dependent form instead, whose footprint is the whole array, and the lowering records that in the module's notes rather than hiding it.

Buffers are placed in consecutive ranges, so array disjointness is discharged once by the allocator rather than once per pair, and every subscript is range-checked against its own buffer — without the check, an out-of-range subscript would silently name a cell of the next buffer.

A worked file

doall-no.mlir is C[i] := A[i] + B[i] over eight points, every iteration independent.

doall-no.mlir 
"builtin.module"() ({
  "memref.global"() {sym_name = "A", type = memref<8xi32>,
                     initial_value = dense<[1, 2, 3, 4, 5, 6, 7, 8]>} : () -> ()
  "memref.global"() {sym_name = "B", type = memref<8xi32>,
                     initial_value = dense<[10, 20, 30, 40, 50, 60, 70, 80]>} : () -> ()
  "func.func"() ({
    %A = "memref.get_global"() {name = @A} : () -> memref<8xi32>
    %B = "memref.get_global"() {name = @B} : () -> memref<8xi32>
    %C = "memref.alloc"() : () -> memref<8xi32>
    "affine.parallel"() ({
    ^bb0(%i: index):
      %0 = "affine.load"(%A, %i) {map = affine_map<(d0) -> (d0)>} : (memref<8xi32>, index) -> i32
      %1 = "affine.load"(%B, %i) {map = affine_map<(d0) -> (d0)>} : (memref<8xi32>, index) -> i32
      %2 = "arith.addi"(%0, %1) : (i32, i32) -> i32
      "affine.store"(%2, %C, %i) {map = affine_map<(d0) -> (d0)>} : (i32, memref<8xi32>, index) -> ()
      "affine.yield"() : () -> ()
    }) {lowerBoundsMap = affine_map<() -> (0)>, steps = [1],
        upperBoundsMap = affine_map<() -> (8)>} : () -> ()
    "func.return"() : () -> ()
  }) {function_type = () -> (), sym_name = "doall"} : () -> ()
}) : () -> ()

The affine.parallel unrolls to eight threads, each reading its own cell of A and B and writing its own cell of C. Read from Lean, the whole file is a program the theorem applies to with nothing further to supply:

Zero false negatives is not a tuning result. A false negative would be a program the scan calls race-free that has a race, and raceSites_nil_iff says the scan's emptiness is equivalent to well-formedness. The fn=0 cell is the theorem showing up in a measurement, not evidence for it.

over-approx [indirect-yes] is the honest entry. A[B[i]] has a footprint of all of A, so that file is refused for its shape as much as for its race — it would be refused even if the indices never met, which is the same precision cost that scatter.prl pays.

The corpus is hand-written.

Seven files, written against DataRaceBench's naming convention to exercise the reader and the verdict path. Feeding it Polygeist-emitted input from the real benchmark sources is the next step and is not done. What the seven do establish is that the interface is the right one: expressible 7/7 with unsupported [] means no operation in any of them fell outside the reader's rules.

Differential execution

There is no preservation theorem for the lowering yet — the claim that the ParProg means what the MLIR module means. Until there is, the translation is validated by running the program twice: once as a lowered ParProg over Int, and once through a separate reference interpreter that evaluates the same module over ℚ, exactly. The two heaps are compared cell by cell.

ProgramThe two runsWhat a disagreement means
race-free, integralmust agreea lowering bug
race-free, floating pointdisagree by the Int truncationthe divergence the notes already named
racymay disagreea second, independent witness of the race

The last row is the anti-vacuity obligation discharged through MLIR. On reduction-yes the reference run takes the canonical schedule and reaches sum = 36; the threaded run reaches something else. The program the verdict rejects really does depend on its schedule.

The converse case is on the same corpus, and matters just as much: antidep-yes is racy and both runs give A = [1, 1, 1, 1, 1, 1, 1, 0], because at this heap every schedule reads a 0 and writes a 1. Agreement is therefore not evidence of race-freedom. The verdict comes from the scan; the differential run only ever tests the translation.

What it refuses

Each of these produces a named error rather than a plausible-looking lowering, and the list of unhandled operation names a file contains is itself an output — so what is missing gets counted rather than discovered one benchmark at a time.

RefusedWhy
multi-block regions, successor listsunstructured control flow, which an inductive ParM cannot encode
scf.if, affine.ifthe conditional tests a value against zero, and the expression language has no comparison operator, so a condition from arith.cmpi has nowhere to go
omp.parallel, omp.wsloopnot read yet; affine.parallel is the marker the lowering uses
func.callno interprocedural handling — also why a module with several functions and no main is refused rather than guessed at
dynamic memref dimensionsno shape to place a buffer from
layout maps, memory spacesstrides other than row-major are not modelled
a computed subscript on a multi-dimensional memrefwould need i·stride + j as an expression, and the array-reference form takes one index
an async.execute whose token is awaited later than the next operationpar joins where it is written; a token awaited later joins later, so reading one as the other would be a different program
an async.execute with operands, or a region with argumentsa dependency token or a captured value; a thread's inputs are the heap and the registers it forked with

The async.execute refusal is the load-bearing one, and it is worth stating why. affine.parallel gives one thread per point of an index box, every thread running the same region at a different index. An unrolled program has no such uniformity — parallel { A[0] := 1 } | { A[1] := 2 } is two different bodies — so it has no affine.parallel spelling at all, and the async dialect is MLIR's own construct for that shape. There, a fork is a group of operations closed by the await that names their tokens, and only that exact shape is read.

Generic form out

The other direction: a layout and a program as a module. A buffer becomes a memref.global with its contents, the body goes in func.func @main after one memref.get_global per buffer, and a fork becomes the async.execute group above.

a fork, emitted 
%0 = "async.execute"() ({ …thread 0… "async.yield"() }) : () -> (!async.token)
%1 = "async.execute"() ({ …thread 1… "async.yield"() }) : () -> (!async.token)
     "async.await_all"(%0, %1) {paralever.label = "chunked sum"} : (…) -> ()

Two things change on the way out, and the emitted file says so in its header. Registers are assignable and SSA values are not, so a register assignment with no memory in it disappears into whatever reads it, and the registers that remain come back renumbered. And a computed subscript wraps on the buffer's length where MLIR's does not, so the two agree on every index in range — which is every index a race-free program uses.

The gate is therefore not a tree comparison. The module is emitted, read back, and compared on everything a theorem would use: the memory, the footprint, the verdict, and the heap a sequential run leaves. Comparing trees would fail on the renumbering and tell you nothing.
