The theorem

Six definitions and one proof. The definitions say what a parallel program is, how it runs, and when a fork is safe; the proof says that a safe fork can be read sequentially without changing any outcome.

A program is data

ParM α is an inductive type with four constructors: return a value, read a location and continue with what was there, write a location and continue, or fork a list of children and continue with all their results. Nothing in the type mentions threads, time, or Lean's runtime.

Two readings of the same term

State is Loc → Val and total: every location exists and holds 0 until written, so no program can create or destroy memory. Against that heap there are two readings of a term.

runSeq is the reference reading. It is a function, total and deterministic: at a fork it runs the children left to right, threading the heap from one into the next.

Lean 4 · Paralever/Core/Access.lean

step is the parallel reading, and it is a relation in disguise: it returns the list of configurations one atomic move can land in. At a fork, any child may move, so the list has one entry per child that can step. A fork whose next accesses conflict steps to a single wrong.

Lean 4 · Paralever/Core/Semantics.lean

Reaches is the reflexive-transitive closure, so every claim about all interleavings is a claim about this one relation. wrong has no successors: a race is absorbing. That choice is Reynolds' grainless semantics, and it is what makes the size of an atomic step irrelevant — a program whose correctness depended on the grain contains a conflicting pair, and a conflicting pair goes to wrong.

Independence is Bernstein's, not ∗

A Footprint is a pair of location lists: what a program reads and what it writes. accesses p σ measures it along p's reference run from σ — a read's footprint includes the cell it read, and the continuation is measured at the heap the read saw, so the measurement is exact for the run it describes rather than a syntactic over-estimate.

Three clauses, and the fourth possible pair is deliberately absent: r₁ ∩ r₂ may be anything at all. A shared read is not a race, and admitting it is not a convenience — it is what decides whether the method reaches real programs.

The third row is matmul. Thread i writes row i of C and reads all of B; thread j writes row j and reads all of B too. Under ∗ the two threads cannot both own B, so the ordinary fork rule does not apply without a fractional-permission or read-sharing extension. Under Bernstein the program is simply independent.

WellFormed p σ lifts Indep to a whole term: at every par node, the children's footprints are pairwise independent, each child is itself well-formed, and so is the continuation. Checking the outermost fork alone would not do — a branch can race with itself while the two branches' total footprints stay disjoint.

Where the children are measured

One detail in accessesChilds carries the proof, and reading past it makes the main lemma look impossible. Each child's footprint is measured from the heap the previous child left:

Lean 4 · Paralever/Core/Access.lean

The machine, meanwhile, lets the tail step at σ, because that is where the machine is. So in the one case of the proof with real content — a non-leftmost child moves — the machine's heap and the reference measurement's heap disagree, and the step has to be shown to see the same values anyway. It does, and the reason is the only place Indep is actually used: the locations the tail reads are not among the locations the head writes, so the head's writes left them alone. Concretely, with p = write 5 1 and q = read 7 (fun v => write 8 v), the two runs agree exactly when σ₁ 7 = σ₀ 7, and that holds because 7 ∉ W(accesses p σ₀) = {5}.

Canonical outcomes, then the equality

The proof is in two steps, and the first does all the work.

1

Canonical outcomes.

If p is well-formed at σ, then Reaches (.run p σ) (.run (.pure r) σ') holds if and only if (r, σ') = runSeq p σ. A well-formed program has exactly one terminal outcome, and runSeq names it. The argument is that runSeq is a conserved quantity: every single step of the machine leaves runSeq of the configuration unchanged, so the value it had at the start is the value it has at the end — and at the end the program is pure r, whose runSeq is (r, σ').

2

Both sides are canonical.

seqPair p q is well-formed whenever parPair p q is, and the two have the same runSeq — the fork's reference reading is the sequential composition. Rewriting both sides of the Iff by step 1 turns the equivalence into that equation.

The N-ary form is proved by induction on the children list, where the cons case is the two-to-N step. A region form — par_seq_eq_region — parallelizes one fork inside a larger program, which is what lets a pipeline be sequentialized one region at a time, since ParSeqEq is an equivalence relation and composes by trans.

From the term to a Bool

WellFormed quantifies over a heap and so is not decidable as written. The surface language ParProg is first-order: addresses are numbers, values are closed arithmetic over registers, and a statement's footprint is computed from the syntax by footprintOf. That makes the obligation a Bool:

Lean 4 · Lang/Core/Prog.lean

wfB is sound and not complete, and the gap is deliberate. A computed address dst[%i] has a footprint of every cell of dst, because the index is not known from the syntax — so three threads writing three distinct cells are refused. When that matters, wellFormedB measures the accesses along the canonical run instead; it is both sound and complete, and it buys the equivalence at one heap. Both routes are offered, and paralever prove picks whichever the program earns.
