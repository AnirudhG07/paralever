paralever

The theorem

Parallel and sequential agree when every fork in the program is independent: no two threads write one cell, and no thread writes a cell another reads. That condition makes the program's outcome unique, and a unique outcome is what collapses the two readings into one equality.

A program is data

Start with a program. Four threads, each adding two neighbouring cells.

Examples/Language/stencil.prl 
const n = 4

buf inp[5] = 1, 2, 3, 4, 5
buf out[4]

parfor i in n {
  %a := inp[i]
  %b := inp[i + 1]
  out[i] := %a + %b
} :: "stencil"

Inside Lean that program is a value of type ParM, not an action. The type has four constructors: return a value, read a cell and continue, write a cell and continue, or fork a list of children and continue with their results.

Lean 4 · Paralever/Core/ParM.lean

Nothing in the type mentions threads, time, or Lean's runtime. Three consequences follow from that shape, and all three are permanent.

BecauseTherefore
par is a constructor, not a function Its meaning is whatever run says it is. Lean proves nothing about it for free, which is why there is a theorem to state at all.
ParM is inductive Only terminating programs can be written. Lean 4 has no coinductive types, so while true is unrepresentable and the boundary is permanent.
The children carry a type-indexed spine The fork is N-ary and each child keeps its own result type. A plain List (ParM α) is rejected by the kernel. The price is that Lean's induction tactic refuses ParM, so proofs go through ParM.inductionOn.

Full detail: docs/program-model.md.

Two readings of the same term

Memory is a function from locations to values, and it is total. Every cell exists and holds 0 until written. Against that heap one term can be read in two ways.

The first is runSeq, the reference reading. It is an ordinary function: at a fork it runs the children left to right, passing the heap from one into the next.

Lean 4 · Paralever/Core/Access.lean

The second is step, the parallel reading. It returns every configuration one atomic move can land in. At a fork that means one entry per child that can move. A fork whose next accesses conflict steps instead to a single wrong.

Lean 4 · Paralever/Core/Semantics.lean

Reaches is the reflexive-transitive closure of step. So a claim about all interleavings is a claim about one relation. wrong has no successors, which is Reynolds' grainless semantics. A program whose correctness depended on the size of an atomic step contains a conflicting pair, and a conflicting pair goes to wrong.

Full detail: docs/semantics.md.

Bernstein's condition, and separation logic's ∗

A footprint is a pair of lists: the cells a program reads, and the cells it writes.

Lean 4 · Paralever/Core/Access.lean

Two forks are independent when neither writes a cell the other touches. That is three clauses. The fourth possible pair, r₁ ∩ r₂, is deliberately absent: a shared read is not a race.

Two threadsSeparation logic's ∗Bernstein
both write xrejectedrejected
one writes x, the other reads itrejectedrejected
both read x, neither writesrejected, because the heap must splitallowed

The third row is matrix multiply, and it is why this project uses Bernstein. Under ∗ two threads cannot both own B, so the ordinary fork rule needs a fractional-permission extension before it applies. Under Bernstein the program is independent as written.

Here is the other side. Both threads write x[0], so no reading of the clauses saves it.

Examples/Language/race.prl 
buf x[1]
buf log[2]

parallel {
  log[0] := 1
  x[0] := 7
} | {
  log[1] := 1
  x[0] := 9
}

Well-formedness is that condition applied to a whole program. At a fork it asks three things: the children's footprints are pairwise independent, each child is itself well-formed, and so is whatever runs after the fork, from the heap the fork leaves.

Lean 4 · Paralever/Core/Access.lean

Every fork is checked, not only the outermost one. Checking the outermost alone would be unsound: a branch can race with itself while the two branches' totals stay disjoint.

Full detail: docs/access.md, and docs/theory.md §8 on why no separation-logic library is used.

Where the children are measured

One detail carries the whole proof. Each child's footprint is measured from the heap the previous child left, not from the heap the fork started in.

Lean 4 · Paralever/Core/Access.lean

The machine does not stagger. It lets the second child move at the heap it is actually in. So in the one case of the proof with real content, the machine's heap and the measurement's heap disagree, and the step has to see the same values anyway.

It does, and this is the only place independence is used. Take p = write 5 1 and q = read 7 (fun v => write 8 v). The two runs agree exactly when σ₁ 7 = σ₀ 7, and that holds because 7 is not among the cells p writes.

Full detail: docs/access.md.

Canonical outcomes, then the equality

The proof is in two steps, and the first does all the work.

1

Canonical outcomes.

A well-formed program has exactly one terminal outcome, and runSeq names it. The argument is that runSeq is a conserved quantity. Every single step of the machine leaves it unchanged, so the value it had at the start is the value it has at the end. At the end the program is pure r, whose runSeq is the answer.

2

Both sides are canonical.

The sequential version is well-formed whenever the parallel one is, and the two have the same runSeq. Rewriting both sides of the equivalence by step 1 turns it into that equation. Independence is never mentioned here.

Lean 4 · Paralever/Theory/WellFormedCanonical.lean

That is wellFormed_canonical, and it is the hard theorem of the project. Both directions are there: the canonical pair is reachable, and nothing else is.

Lean 4 · Paralever/Theory/Sequentialize.lean

The N-ary form follows by induction on the children list, where the cons case is the two-to-N step. A region form parallelizes one fork inside a larger program, which is what lets a pipeline be sequentialized one region at a time.

Full detail: docs/theory.md and docs/decomposition.md.

The final ParSeqEq theorem

WellFormed quantifies over a heap, so it is not decidable as written. The surface language is first-order: addresses are numbers, and a statement's footprint is computed from its syntax. That turns the obligation into a Bool.

Lean 4 · Lang/Core/Prog.lean

wfB is sound but not complete, and the gap is deliberate. This program writes three distinct cells, one per thread, and is still refused.

Examples/Language/scatter.prl 
buf idx[3] = 2, 0, 1
buf dst[3]

parfor t in 3 {
  %i := idx[t]
  dst[%i] := 1
}
paralever check Examples/Language/scatter.prl 
Examples/Language/scatter.prl
  memory:   idx[3] @0, dst[3] @3  (6 cells)
  reads:    {idx[0], idx[1], idx[2]}
  writes:   {dst[0], dst[1], dst[2]}
  threads:  3
  rounds:   2 parallel, 6 sequential
  verdict:  this heap   Proved: Yes — no two threads touch one cell here
            any heap    RACE found — with idx[0] = -1: dst[0] written by both threads

The index comes from memory, so the footprint of dst[%i] is every cell of dst. At the declared heap the exact search settles it anyway. At every heap the answer is no, and it is right: set idx[0] to -1 and the program does race. Both routes are offered, and paralever prove writes whichever theorem the program earns.
