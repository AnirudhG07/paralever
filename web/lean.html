paralever

The Lean library

Six libraries and one executable. Core/ and Theory/ need no Mathlib at all, so a single file can be typechecked on its own in a second.

Building it

console 
lean Paralever/Core/ParM.lean    # typecheck one file — fast, no dependencies needed
lake exe cache get               # Mathlib oleans, before a first full build
lake build                       # everything
lake build Examples              # just the worked examples
grep -rn "sorry" Paralever/      # the no-sorry gate
lake exe paralever --help        # the command line

The toolchain is pinned to leanprover/lean4:v4.34.0, with Mathlib and iris-lean at the same tag. Mathlib is never imported through an umbrella file: a lemma is imported from the module it actually lives in, which is what keeps a standalone lean <file> check viable on the files that matter most.

Lean's induction refuses ParM

This is the one thing that will surprise someone reading a proof for the first time. ParM's par constructor takes a Childs ParM αs — a nested inductive family — and the automatically generated recursor is not in the shape the tactic wants, so every proof goes through one of two hand-written principles instead.

UseWhen
ParM.inductionOnthe statement is about one program
ParM.mutualInductionthe statement is about a program and its children's spine at once — which is most of the theory, since a fork's property is stated in terms of its children's

The reason the spine exists at all is worth recording, because the obvious alternative does not typecheck. List (ParM α) with a constructor-local α is rejected by the kernel — "nested inductive datatypes parameters cannot contain local variables" — so the children carry their own type list, and that index is what keeps each child's result type static. The N-ary theorems are then proved by induction on the children list, where the cons case is the two-to-N step.

The worked examples

Examples/ is one tree with Lean files, .prl files and .mlir files side by side. The source files are read and compiled from inside Lean while the Lean file elaborates, so no command line is involved and by decide sees the compiled program rather than the reader.

Programs/ — the method, on real algorithms

Every file follows the same chain, and the two links are independent: changing the algorithm does not touch link 2, and changing the decomposition does not touch link 1.

Races/ — what failure looks like

File
Caught.leantwo programs where the conclusion of the theorem is false, not just its hypothesis
Report.leanreading a counterexample: the interleaving, and the heap the sequential run leaves
Pointers.leana stray index — rejected in three shapes, and accepted in one, because this is equivalence, not memory safety

Caught.lean is the file that keeps the main theorem honest. If the independence hypothesis were decoration, the conclusion would hold without it; these two programs are the witnesses that it does not. The other standing obligation is a loop-carried dependence — A[i] := A[i-1] + 1 — kept as a case whose obligation is unprovable.

Dependencies, and what is deliberately absent

Mathlib and iris-lean, and nothing else. From iris-lean the library takes its propositional interface and proof mode: instantiating that interface at this project's own State → Prop buys a few dozen proof-mode tactics for one instance declaration.

HeapLang is deliberately not imported, and read only as a template. Its par is derived from an unstructured fork; it is nondeterministic in allocation and prophecies; it has no arrays; and its parallel-composition rule is unary, so it cannot express an equivalence at all. Any one of those would be enough.

Several other systems were read for design and are not required — deliberately, since each would add a toolchain pin. The reading list and the reasons are in docs/papers.md; every rejected alternative has its own note in docs/, which is where rationale lives. Source files carry a one-line pointer to the paper or the design note a declaration comes from, and nothing more: the rule is that every definition, hypothesis and design choice traces to one or the other.
