We parallelize programs for GPU/TPU, etc. targetting True Parallelism in most cases. The primary question that arises:

Is par = seq correct? under every schedule

seq — the statements run one after another, on one core. par — the branches of a parallel block run at the same time, and the block ends when all of them have.

Part 1 · Background

Hoare triples, ∗-disjointness, and what Concurrent Separation Logic (CSL)'s soundness theorem gives you

Why Hoare triples are not enough?

Consider the below counterexample:

C₁ : [p] := 5; y := [p]write to [p], then read it back
C₂ : [p] := 8write to the same [p]
Let p points at xso both commands write the cell holding x
{true} C₁ {y = 5}
{true} C₂ {true}
{true} C₁; C₂ {y = 5}by sequencing, y = 5
{true} C₁ ∥ C₂ {y = 5}false · a schedule runs C₂ between the write and the read, leaving y = 8

  • A triple {P} C {Q} says that if P holds and C terminates then Q holds. It quantifies over the starting state and over nothing else — in particular not over what another thread does while C runs.

  • So the first triple is proved as though its command ran alone. y := [p] reads back the value the command itself wrote, which is true of every run in which nothing else touches [p].

  • The schedule that runs C₂ between that write and that read does touch [p], so the assumption the proof was built on no longer holds, and y ends at 8.

  • A triple has no way to say this cell is mine, so it cannot exclude that schedule. Ownership is the missing notion, and it is what separation logic adds.

Separation Logic's ∗-disjointness

l ↦ vthe heap cell l holds v · exclusive
P ∗ P′the heap splits into two disjoint-domain pieces, one satisfying each
{P} C {Q}     {P′} C′ {Q′}
{P ∗ P′}   C ∥ C′   {Q ∗ Q′}
C modifies no variable free in P′, C′, Q′, and conversely · O'Hearn, CONCUR 2004

  • l ↦ v says the heap is exactly one cell, l, and it holds v. Holding it is exclusive: no other assertion standing beside this one may mention l.

  • P ∗ P′ says the heap splits into two pieces whose domains are disjoint, one satisfying each side. The existence of that split is part of the claim, not a remark about it.

  • Each premise of the rule mentions one thread, and the conclusion holds for every interleaving. Disjointness is what pays for that step: neither thread can reach a cell the other owns, so there is nothing for an interleaving to disturb.

  • O'Hearn states this as two hypotheses — a thread accesses only what it owns, and at every moment the state partitions into the parts owned by each thread and by each resource.

Sharing comes back as a loan, and the rules are sound by a trace semantics

{(P ∗ RI₃) ∧ B} C {Q ∗ RI₃}
{P}   with r when B do C   {Q}
each resource name r carries an invariant RI₃ · two with regions for the same r never overlap in time

  • r is a resource: a name for a region of the heap that no thread owns. Every r carries an invariant RI_r, the assertion describing the states that region is allowed to be in.

  • Outside a region a thread knows nothing about those cells. with r when B do C lends RI_r to the thread on entry; C may break it while it runs, and has to restore it before the region ends.

  • RI_r must be precise, meaning it pins down one sub-heap rather than any of several. Without that the hand-back is undefined — the thread would not know how much of the heap it is returning.

  • Brookes proves both rules sound in a semantics of action traces in which a racing step is a catastrophic error, so a program with a race proves nothing.

Parallel Decomposition · Brookes, CONCUR 2004, Thm. 21
If a trace of C₁ ∥ C₂ runs from a state split as σ₁ ∗ σ₂ and the components' footprints stay separate, then that trace is an interleaving of a trace of C₁ from σ₁ and a trace of C₂ from σ₂, and the final states recombine as σ₁′ ∗ σ₂′.

The heap splits, and that split is also the hypothesis: it must already hold of σ. Two threads reading a₀ have no such split, and C₁; C₂ is never mentioned.

The conclusion is about the states, not only the traces: each thread's final heap σᵢ′ is what that thread alone produces from its own half, and σ′ is their disjoint union. That is what makes the disjoint-concurrency rule sound — Q₁ holds of σ₁′ and Q₂ of σ₂′, so Q₁ ∗ Q₂ holds of σ′. The premise is a heap already written as σ₁ ∗ σ₂ with each thread confined to its own half, and two threads that both read a₀ cannot be divided that way: whichever half holds a₀, the other thread's local run steps outside its heap. Our hypothesis asks for no split, only Bernstein independence, and our conclusion is the one this lemma does not state — that C₁ ∥ C₂ and C₁; C₂ reach the same outcomes, in both directions, under every schedule.

∗ forbids a shared read that nothing can go wrong with

  • Each side needs a₀ ↦ u, so the conclusion needs (a₀ ↦ u) ∗ (a₀ ↦ u) ⇒ false.

  • A resource r serializes the two reads instead of allowing them.

  • Fractions do allow them: a₀ ↦_{1/2} u each, carried through every lemma.

  • Bernstein checks writes only, so read-read is no conflict.

“there is no way to prove the obviously valid formula ⊢ {z ↦ 1} x:=[z] ∥ y:=[z] {x = y = 1 ∧ z ↦ 1}, since the logic requires both processes to ‘need’ to own the heap cell denoted by z, separately. Nevertheless, the trace semantics handles this issue (and this example) correctly, so here is a place where the semantics is ahead of the logic.” Brookes, A semantics for concurrent separation logic, CONCUR 2004

To dereference a₀ the left premise must hold a₀ ↦ u and the right premise the same cell, and one cell does not split into two pieces that each contain it — so the rule does not apply, to a program whose answer no schedule can change. Handing a₀ to a resource takes it out of both preconditions, but then every read sits inside with r do … and two such regions never overlap in time; matmul would put each element it reads into a critical region and give up the parallelism it was written for. Fractional permission is the real repair, and it moves the cost into the specifications: a fraction for every shared cell, threaded through every lemma.

This is O'Hearn's own argument, used there to show that [10]:=42 ∥ [10]:=6 has no derivable triple; pointed at reads it rejects a deterministic program instead. The claim is not that CSL cannot verify this — with fractions it can. The claim is about the shape of the obligation, and matrix multiplication is this example at scale: every row of A is read by every thread in a row block.

Part 2 · Our claim

Independent branches can be run either way, and the answer does not change

One theorem about two programs, with a hypothesis the kernel evaluates — rather than a bound on one program's postcondition.

What the literature proves, and what it leaves open

Independence is Bernstein, computed from the syntax

@[simp, grind .] def Indep (f₁ f₂ : Footprint) : Prop := Disjoint f₁.writes f₂.writes ∧ Disjoint f₁.writes f₂.reads ∧ Disjoint f₂.writes f₁.reads

  • w₁∩w₂ = w₁∩r₂ = w₂∩r₁ = ∅ — shared reads are allowed

  • ∗ would forbid them, and so forbid matmul: disjoint C[i*n+j], overlapping rows

  • footprintOf is a fold over the syntax, so the check is decide, not a proof

reads 0,1 · writes 2thread 1
reads 0,1 · writes 3thread 2
→indepB = true
acceptedsame cells read, different cells written

WellFormed is that check at every par, along the run

def WellFormed {τ : Type} : ParM τ → State → Prop | .pure _, _ => True | .read l k, σ => WellFormed (k (σ l)) σ | .write l v k, σ => WellFormed (k ()) (σ.update l v) | .par cs k, σ => let r := runChilds cs σ IndepAll (childFootprints cs σ) ∧ WellFormedChilds cs σ ∧ WellFormed (k r.1) r.2

  • accesses p σ is the footprint of running p from σ: the cells it reads and the cells it writes, as two lists.

  • A par node asks for three things — the children's own footprints are pairwise independent, each child is itself well-formed, and so is the continuation from the heap the children leave.

  • A read or write is never a condition; it only advances the heap the next check is measured against. All of the content sits at par nodes.

  • Checking the outermost par alone is unsound, which is why the recursion goes to the bottom of the tree.

WellFormed mentions a heap σ, so as stated it is a predicate about one starting state. wfB is the same condition with the σ removed — read off the syntax — and wfB_wellFormed closes that gap: wfB s = true gives WellFormed (execPar s ρ) σ for every ρ and every σ. That is the lemma the next slide's hypothesis rests on.

Independent branches agree with p; q under every schedule

theorem par_seq_eq {s : ParProg} (h : wfB s = true) (ρ : Regs) (σ : State) : ParSeqEq (execPar s ρ) (execSeq s ρ) σ := bys:ParProgh:s.wfB = trueρ:Regsσ:State⊢ s.execPar ρ ∥≡ s.execSeq ρ from σ

  • ParSeqEq p q σ — the two reach the same outcome set from σ, not one trace

  • hypothesis is a Bool the kernel evaluates; conclusion quantifies over schedules

  • time_le rides along: the parallel reading never needs more rounds

The schedule does not appear in the obligation. Proved once, every program afterwards pays one decide on a footprint rather than a proof about interleavings.

Part 3 · Programs as data

One branching constructor, and a footprint computed from the syntax

ParM is an inductive type, so a program is a tree Lean can take apart; the obligation is a Bool on two lists of addresses.

seq is a spine; par is the only node that branches

Same leaves, same order, one node different. paralever { s₁; …; sₙ } is right-nested seq, so every program is a spine until a parallel block puts a fork in it.

This is the slide that teaches the two constructors. seq threads the heap and the register file from one child to the next; par hands every child the same starting state and joins. Everything later — the check, the theorem, the rewrite — is about par nodes only.

Nobody states what a program touches — footprintOf evaluates it

#eval ParProg.footprintOf (matmul 2) { reads := [0, 4, 1, 6, 0, 5, 1, 7, 2, 4, 3, 6, 2, 5, 3, 7], writes := [8, 9, 10, 11] }two lists of addresses, obtained by reduction — not an annotation, not a lemma

  • accesses p σ is the footprint a run actually has. It depends on σ, so a claim about it is a claim about every heap.

  • footprintOf s reads the same two lists off the syntax tree and mentions no heap at all, so Lean evaluates it.

  • execPar_accesses_sub is the one thing that needed proving, and it is proved once for all programs: the computed lists contain the cells any run touches.

theorem execPar_accesses_sub (s : ParProg) (ρ : Regs) (σ : State) : (accesses (execPar s ρ) σ).Sub (footprintOf s) := execPar_accesses_sub_all.1 s ρ σ

So a user's obligation is a Bool the kernel computes, never a lemma they write: by decide on wfB, which runs footprintOf and then the pairwise independence test on the lists above. Containment in one direction is all that is needed — an over-approximation costs precision and never soundness. The three cases: a literal address gives an exact footprint, a computed address A[B[i]] gives the whole array, and a branch gives the union of its two sides. Examples/Language/Scatter.lean is where that over-approximation bites: raceSites finds no race and wfB still refuses.

parallel { [0] := 1 } | { parallel { [1] := 2 } | { %0 := [1] } }outer footprints {0} and {1} are disjoint — a top-level check passes

the inner `par` writes and reads `[1]` concurrently`wfB` recurses, so it rejects this

A check that only looked at the outermost fork would be unsound, which is why wfB is defined by recursion on the whole tree.

Part 4 · The proof

Four pieces, and the schedule appears in exactly one of them

Where the difficulty actually is, and the program on which this equality is false.

The proof is four steps, and only one is about schedules

ParM is a nested inductive, so Lean's induction refuses it: every step runs through ParM.mutualInduction, and the N-ary case is an induction on the children list.

The difficulty, on two children

p = write 0 1 q = read 1 (λv. write 2 v)disjoint: p writes {0}, q reads {1} and writes {2}
→two readings
runSeq measures q at σ[0↦1]after p has run
a real schedule may run q at σbefore p has run

  • these are different heaps, so the two readings of q are a priori different runs

  • independence is what makes them agree: q reads [1], p writes [0], so the cell q looks at holds the same value in both

  • the induction therefore carries the footprint along with the equality — one level down, the footprint conjunct is what pins the replayed heap to the right one

The theorem is that every reachable terminal configuration of a well-formed par is the same one, and runSeq names it. The schedule enters the proof here and nowhere else.

Every configuration a schedule reaches computes the same runSeq

theorem wellFormed_canonical {τ : Type} (p : ParM τ) : ∀ σ r σ', WellFormed p σ → (Reaches (.run p σ) (.run (.pure r) σ') ↔ (r, σ') = runSeq p σ) := wellFormed_canonical_all.1 p

  • One step leaves runSeq P σ unchanged, and can only shrink the footprint — step_combined.

  • One step keeps WellFormed, whichever branch moved — WellFormed_preserved.

  • Iterate along the whole chain: every reachable P', σ' has runSeq P' σ' = runSeq P σ — runSeq_invariant_chain.

  • At a .pure r endpoint runSeq is (r, σ'), which gives (r, σ') = runSeq P σ: the →.

  • For ←, run child 1 to completion, then child 2, then step into the continuation — reachesChilds_canonical.

Step 1 is where independence does the work, and it is the only hard case. The branch that moves second is replayed against a heap runSeq never measured it from. step_locality says a step replays unchanged between two heaps that agree outside a set of cells; Indep says the branch that moved writes nothing the other one reads or writes, so the two heaps do agree outside that set; and pinning the replayed heap down exactly needs the footprint conjunct of this very induction, one level down. That is why step_combined proves the outcome and the footprint together rather than as two lemmas — each half needs the other.

The ← direction needs no induction hypothesis about schedules at all: it exhibits one schedule. Running a child to completion is this same theorem one level down, which is why the two halves are mutually inductive.

wfB gives well-formedness at every heap, by one induction

theorem wfB_wellFormed {s : ParProg} (h : wfB s = true) (ρ : Regs) (σ : State) : WellFormed (execPar s ρ) σ := wfB_wellFormed_all.1 s h ρ σ

  • Induction over the syntax. load, store, set are trivial — only par carries a condition.

  • At a par: indepAllB held of the computed footprints, and Indep is antitone, so it holds of the real ones at σ — indepAll_childFootprints.

  • The sequential side has no par node, so its WellFormed is True by structure — wfB_wellFormedSeq_all.

  • Hand-written ParM instead of a ParProg: WellFormed_par_intro asks for the same three obligations, proved rather than decided.

This is the only place the quantifier over heaps is discharged, and it is discharged once, in the library: σ is universally quantified in the statement, so a program's own obligation never mentions a heap. That is what makes by decide sufficient afterwards.

The antitonicity step is the one worth saying aloud. execPar_accesses_sub gives accesses (execPar s ρ) σ ⊆ footprintOf s, and Indep.mono_left/mono_right say independence survives shrinking either side — so a bound that passes the test is enough, and a data-dependent address contributing its whole array is sound for exactly this reason.

Examples/Programs/SharedReads.lean is the hand-proved route: wellFormed_minmax discharges the three obligations for findMin ∥ findMax, where both branches read all three input cells.

Where this equality is false: one shared resource

observer = write 1 7 (λ_. read 0) mutator = write 0 99Examples/Races/Caught.lean · σ₀ has cell 0 = 1
→par
y = 99mutator ran first · par_reaches
→seq
y = 1only outcome · seq_runSeq

  • put both accesses inside with r do … and CSL proves the program, with RI_r = ∃v. 10 ↦ v; by Brookes's corollary it is race free

  • race freedom is strictly weaker than determinism: the ∥ rule joins postconditions with ∗, which records no ordering — the rule is designed to forget the schedule

  • so ParM has no resource, no lock, and no unstructured fork, and the conclusion would be false if it had — not_parSeqEq proves the failure, not_indepAll refutes the hypothesis

Both sides terminate normally here and simply disagree, which is the case a reader is entitled to worry about.

max at a fork is derived, not assumed

theorem time_le {s : ParProg} (h : wfB s = true) (ρ : Regs) (σ : State) : time (execPar s ρ) σ ≤ time (execSeq s ρ) σ := time_execPar_le_all.1 s ρ σ h

  • work counts memory operations and is unchanged by forking — work_par_eq_seq

  • time counts rounds, where a round advances every ready child by one step

  • nothing in the cost semantics stipulates max at a fork: it falls out of the same independence hypothesis, on the same Bool — and time_par_lt_seq_single makes the inequality strict when both branches do work

Conflating work with time is the usual mistake. Parallelism buys nothing in total operations, and the theorem says so.

Part 5 · The language

Memory, registers, one fork — and the check run on user code

ParProg is the surface syntax a user writes; wfB is the same obligation, decided.

The language: memory, registers, and one fork

Over-approximation costs precision, never soundness: execPar_accesses_sub proves the computed footprint contains every cell actually touched, at every heap.

Four programs, in increasing order of what they need

A read-only sum, then overlapping reads, then recursion, then an in-place update — and the same two lines discharge every one of them.

A matmul: the reads overlap heavily, and that is the point

A merge sort: the same recursion twice, parPair against seqPair

def mergeSortPure : List Int → List Int | [] => [] | [x] => [x] | x :: y :: rest => let xs := x :: y :: rest let mid := xs.length / 2 mergePure (mergeSortPure (xs.take mid)) (mergeSortPure (xs.drop mid))def mergeSortPar (N : Nat) : Nat → Nat → ParM Unit | lo, hi => if _h : hi - lo ≤ 1 then .pure () else let mid := lo + (hi - lo) / 2 ParM.bind (ParM.parPair (mergeSortPar N lo mid) (mergeSortPar N mid hi)) (fun _ => ParM.bind (mergeStep mid hi N (hi - lo) lo mid lo) (fun _ => copyBack N (hi - lo) lo lo))

  • mergeSortSeq is the same definition with seqPair for parPair — nothing else differs

  • here the obligation cannot be decided: the recursion is in N, lo, hi, so independence comes from an interval argument — the two halves touch [lo,mid) and [mid,hi), which are disjoint

  • mergeSortPar_wellformed N lo hi (hi ≤ N) σ holds for every range and every heap, and seq_eq_par follows for the whole recursion rather than the top split

rewrite_sound: seq = par for the rewrite, with no hypothesis

theorem rewrite_sound (p : ParProg) (ρ : Regs) (σ : State) : (runSeq (execPar (rewrite p) ρ) σ).2 = (runSeq (execSeq p ρ) σ).2 := byp:ParProgρ:Regsσ:State⊢ (runSeq ((rewrite p).execPar ρ) σ).snd = (runSeq (p.execSeq ρ) σ).snd

  1. execPar and execSeq agree under runSeq — execPar_runSeq_all

  2. execSeq of a par restores the register file, so a chain of forks never advances it: every thread of the whole plan runs at the initial registers — stages_seqAll

  3. threads in order, each at the initial ρ, are the chain, when no register flows between them — fork_heap

  4. a chain of blocks runs like the flat chain — runSeq_block_map

  5. the plan's units are the program's statements — plan_units, atoms_flatten, runSeq_flatten

Step 2 carries the proof: a fork restores ρ, so a chain of forks leaves the top-level plan in the situation fork_heap already handles, one level up. rewrite checks its own plan and returns p unchanged if the check fails — which is why the theorem needs no hypothesis.

Part 8 · MLIR

One front end, so a benchmark is not translated by hand

Hand-translating a benchmark suite is the dominant threat to validity for anything measured on one, because the translation is part of what is measured and is itself unverified.

MLIR as the one front end

  • N languages against one converter, instead of one front end per language — and stage 1 is replaceable, so a hand-written .mlir feeds the same interface

  • generic form, not each dialect's assembly: --mlir-print-op-generic prints every op the same way, so one reader covers affine, memref, arith and func

  • not LLVM IR — unstructured br and phi nodes have no encoding in an inductive ParM, and going through a loop structurizer destroys the affine maps the lowering depends on

MLIR.lower is a Lean function, so the translation is an object we can state a theorem about. The target is footprint preservation, which turns "trust the translator" into a proof obligation.

An affine map is already a footprint function

"affine.store"(%v, %A, %i, %j) {map = affine_map<(d0, d1) -> (d0, d1)>}the map applied to (i, j) is the subscript — no analysis, no inference
▼
Layout.at "A" [i, j] = A.base + i·cols + jrange-checked against its own buffer, because `Layout.at` is total
▼
wr (i, j) = [that cell]which is exactly what `wfB_parFor_of_lists` asks for

  • loops are unrolled at lowering time, so the subscript is a literal Nat and the footprint stays exact — proportional to the number of accesses, not to the size of the array

  • that matters for evaluability, not only precision: indepB is quadratic in list length, so an over-approximated footprint on a large array is unevaluable rather than merely imprecise

  • unrolling has a ceiling — decide on wfB (matmul n) is 6.6 s at n = 8 and 19 s at n = 10, and native_decide is prohibited — so about a hundred threads, and past that a kernel lemma at symbolic n

Layout.of places buffers in consecutive ranges, so array disjointness is discharged once by the allocator rather than once per pair.

Limits

  • registers cannot be renamed away — yet. noRegFlow is on raw read sets, stronger than the liveness atoms establishes, so a chain reusing %0 is declined and returned sequential

  • memory cannot be renamed at all. A Loc is reached by a computed address, so the cell is the name — privatization, the commonest OpenMP clause, is out of reach

  • footprints over-approximate. A[B[i]] reports the whole array; whileAtMost reports the branch union — conservative, never unsound

  • ParM is inductive, so while true is unrepresentable; and whether order preservation itself costs depth is open

Conclusions

  • One theorem, then arithmetic. wfB s = true ⇒ execPar s ∥≡ execSeq s, every schedule, arbitrary programs, kernel-checked — so each program pays decide, not a proof about interleavings

  • The rewrite is proved, not checked. rewrite_sound has no hypothesis: the pass is untrusted, the gate is proved, and the plan's order preservation makes the bookkeeping structural

  • Optimal where fork–join allows. Depth meets the DAG critical path on interleaved chains and on merge sort; the N's gap of 8 vs 7 is the shape, and the 7-tree is racy
