The fundamental question for (truly) parallelizing programs

paralever { [0] := 3; [1] := 4; %0 := [0]; [2] := %0 * %0; %1 := [1]; [3] := %1 * %1; %2 := [2]; %3 := [3]; [4] := %2 + %3 }nine statements, one core
→parallelize
paralever { [0] := 3; [1] := 4; parallel { %0 := [0]; [2] := %0 * %0 } | { %1 := [1]; [3] := %1 * %1 }; %2 := [2]; %3 := [3]; [4] := %2 + %3 }both leave the heap [3, 4, 9, 16, 25]

One run of each agrees. A parallel program has many runs, and the question is about all of them:

?
Is par = seq correct?
  • schedule
  • starting heap
  • register state

seq — the statements run one after another, on one core. par — the branches of a parallel block run at the same time, and the block ends when all of them have.

Two questions, and one checker answers both

1 · the parallel you wrote — is par = seq?par p q ≡ seqPair p q, under every schedule
2 · the one you did not — is the program parallelizable, and is that fork correct?autoPar proposes it; rewrite_sound proves it with no hypothesis

  • Both questions reduce to one Boolean on the program text, wfB, and one theorem about it.

  • wfB s = true is decided by decide — kernel-checked arithmetic on the footprints the syntax gives, with no proof about interleavings per program.

  • When it is false the answer is an interleaving: a schedule replayed against the semantics, ending in a heap the sequential reading does not produce.

A Hoare triple cannot say "this cell is mine"

C₁ : [p] := 5; y := [p]write to [p], then read it back
C₂ : [p] := 8write to the same [p]
{true} C₁ {y = 5}
{true} C₂ {true}
{true} C₁ ∥ C₂ {y = 5}false · a schedule runs C₂ between the write and the read, leaving y = 8

  • A triple {P} C {Q} quantifies over the starting state and over nothing else — in particular not over what another thread does while C runs.

  • So the first triple is proved as though its command ran alone: y := [p] reads back the value the command itself wrote, which holds of every run in which nothing else touches [p].

  • The schedule that runs C₂ between that write and that read does touch [p], and the assumption the proof rests on is gone.

  • Ownership is the missing notion, and it is what separation logic adds.

∗ forbids a shared read that nothing can go wrong with

{P} C {Q}     {P′} C′ {Q′}
{P ∗ P′}   C ∥ C′   {Q ∗ Q′}
O'Hearn, CONCUR 2004 · P ∗ P′ asserts the heap splits into two disjoint-domain pieces
thread (i, j): %s := 0 for k in n { %s += A[i,k] * B[k,j] } C[i,j] := %sn² threads of a matrix multiply
→which check?
∗-disjointness · REJECTSthreads (0,0) and (0,1) both read row A[0, ·]
Bernstein · ACCEPTSthe shared cells are read by both and written by neither

A separating conjunction splits the heap into disjoint domains, so two threads may not even name one cell. Two threads reading one cell is the case every real kernel is built on, and no interleaving of two reads can disagree. What we need is a relation that permits it.

CSL recovers sharing through a resource r with a precise invariant RI_r, lent to one thread at a time by with r when B do C. That is mutual exclusion — the right tool for a shared counter, and a serialization of exactly the reads a matmul wants to run at once.

Memory is a function, and one equation carries the whole proof

abbrev State := Loc → Valdef update (σ : State) (l : Loc) (v : Val) : State := fun k => if k = l then v else σ k

  • Total — there is no unallocated cell and no crash on a bad read, so no definedness side condition is ever carried. Ownership is a footprint, not a heap domain.

  • Addresses are numbers, so "is i*n + j inside [b, b+len)?" is linear arithmetic and a machine decides it.

  • update_other is the one load-bearing fact. Everything that follows lifts it from one cell to whole programs: to one program, to a program observed on two heaps, to two sibling branches, and finally to one step of an arbitrary interleaving.

A program is a tree, and par is the only node that branches

inductive ParM : Type → Type 1 where | pure {α : Type} : α → ParM α | read {α : Type} : Loc → (Val → ParM α) → ParM α | write {α : Type} : Loc → Val → (Unit → ParM α) → ParM α /-- Fork every child at once, then continue with all their results. The only constructor whose meaning Lean does not already fix: `run` interprets it by interleaving, which is what makes the sequentialization theorem non-vacuous. -/ | par {β : Type} {αs : List Type} : Childs ParM αs → (Results αs → ParM β) → ParM β

  • A program is data, so "for every program p …" is an ordinary quantifier, and par is a constructor whose meaning Lean does not already know.

  • Lean's Task could not host this: (Task.spawn f).get = f () holds by rfl, so parallel and sequential would be the same term and every theorem about them vacuous.

  • par is N-ary and heterogeneous from the start — one node with a children spine, not a nest of binary forks — so there is no separate metatheory for k-way forks.

  • ParM is inductive, so while true is unrepresentable: only terminating programs exist, and that boundary is permanent rather than a gap.

runSeq walks the tree left to right, so it names exactly one answer

def runSeq {τ : Type} : ParM τ → State → τ × State | .pure a, σ => (a, σ) | .read l k, σ => runSeq (k (σ l)) σ | .write l v k, σ => runSeq (k ()) (σ.update l v) | .par cs k, σ => let r := runChilds cs σ runSeq (k r.1) r.2

  • runSeq is a function, so it returns one answer and one heap. It is the reference reading, and the theorem's whole job is to show the parallel machine cannot land anywhere else.

  • It is defined on the same tree the parallel machine runs, not on a translation of it, so "the sequential reading of this program" needs no separate language.

  • For a fork it runs the children left to right, threading the heap: child 2 starts where child 1 finished.

Footprints are measured along that run — staggered, and that is the crux

def childFootprints {αs : List Type} : Childs ParM αs → State → List Footprint | .nil, _ => [] | .cons p ps, σ => accesses p σ :: childFootprints ps (runSeq p σ).2
childFootprints Π[ p q ] σ₀ = [ (reads [], writes [5]), (reads [7], writes [8]) ]the second entry was measured at σ₁, not at σ₀

This gap is the entire technical content of the theorem. It is closed once, and used in exactly one case of one lemma.

Independence is Bernstein, and WellFormed asks it at every fork

def Indep (f₁ f₂ : Footprint) : Prop := Disjoint f₁.writes f₂.writes ∧ Disjoint f₁.writes f₂.reads ∧ Disjoint f₂.writes f₁.reads
W₁ ∩ W₂ = ∅C1 · no cell written twice
W₁ ∩ R₂ = ∅C2 · nothing written then read
W₂ ∩ R₁ = ∅C3 · nor the other way round
R₁ ∩ R₂ · unconstrainedthere is no fourth clause, and that is the point
def WellFormed {τ : Type} : ParM τ → State → Prop | .pure _, _ => True | .read l k, σ => WellFormed (k (σ l)) σ | .write l v k, σ => WellFormed (k ()) (σ.update l v) | .par cs k, σ => let r := runChilds cs σ IndepAll (childFootprints cs σ) ∧ WellFormedChilds cs σ ∧ WellFormed (k r.1) r.2

  • Checking only the outermost fork is unsound — a nested fork inside a thread can race on cells the outer check never compares — so the obligation recurses into every par node.

  • Each node is checked against the heap that node sees along the canonical run, which is what makes the obligation a statement about the program rather than about one heap.

  • The three clauses are used exactly: two of them close the staggered-measurement gap, and all three are what excludes a race. Nothing in the definition is spare.

The machine: one child moves, or the fork joins, or it is wrong

def step {α : Type} : ParM α → State → List (Conf α) | .pure _, _ => [] | .read l k, σ => [.run (k (σ l)) σ] | .write l v k, σ => [.run (k ()) (σ.update l v)] | .par cs k, σ => if racingAll (nextAccsChilds cs) then [.wrong] else match allPure cs with | some vs => [.run (k vs) σ] | none => (stepChilds cs σ).map fun r => match r with | some x => .run (.par x.1 k) x.2 | none => .wronginductive Reaches {α : Type} : Conf α → Conf α → Prop where | refl {c} : Reaches c c | tail {c c' c''} : Reaches c c' → c'' ∈ stepC c' → Reaches c c''
a `par` offers every ready childso every interleaving is a Reaches path
two ready accesses collide → wrongabsorbing: a racy program reaches no answer at all

Races go to wrong rather than to a wrong answer, following Reynolds' grainless semantics. That is what makes the atomic grain irrelevant: there is no "last writer wins", so no theorem here depends on how coarsely a write is implemented.

The theorem: a well-formed program has exactly one reachable outcome

theorem wellFormed_canonical {τ : Type} (p : ParM τ) : ∀ σ r σ', WellFormed p σ → (Reaches (.run p σ) (.run (.pure r) σ') ↔ (r, σ') = runSeq p σ) := wellFormed_canonical_all.1 p

  • Read it as an iff, because both halves do work. → is safety: no schedule terminates anywhere else. ← is liveness: that outcome is actually reached.

  • Without liveness the theorem would be satisfied by a program with no terminating execution at all, which is how a soundness statement can be true and empty.

  • Confluence and normalization, in one biconditional, for a language whose fork is N-ary.

Two ways to attack it fail, and the third is a conservation law

1 · induct on steps, comparing the two machinesfalse — after one step the parallel machine has done q's read and the sequential one p's write: there is no step-by-step correspondence
2 · enumerate the scheduleshopeless — two children of n and m steps give C(n+m, n) interleavings, and children nest
3 · find a quantity that never changescomputable at any configuration, invariant under stepping, and equal to the answer at the end

  • If such a quantity exists, every terminating path must end at the same answer — the quantity was fixed at the start and the end merely reads it off. Whatever route a ball rolls down a hill, its energy at the bottom is the same, so the route need not be known.

  • The candidate is already in hand: Φ(P, σ) := runSeq P σ. It is computable at any configuration — apply the function — and at pure r, σ′ it is (r, σ′) by runSeq's own first line.

  • So the plan: Φ survives one step; WellFormed survives one step, so the first fact applies again; iterate along the path; read Φ off at the end.

The whole difficulty is one equation: σ₁ 7 = σ₀ 7

p = write 5 1 · q = read 7 (λv. write 8 v) at σ₀the tail steps first: q performs its read at σ₀, so q₃ = write 8 (σ₀ 7)

That single equation is the entire difficulty of the theorem. Everything that follows is machinery for saying it in general: at N children instead of two, and at an arbitrary depth of nesting.

Conservation: every step leaves runSeq exactly where it was

Every row but the last is runSeq's own defining equation, read in the other direction. The last row is the theorem.

The one case with content: a child that is not the leftmost moves

  • Move 1 is where Indep is spent: the head's footprint is independent of every later child's, so the tail computes the same footprint and the same answer at σ as at τ₁.

  • Move 2 is locality with F taken to be the tail's writes — the same lemma, in the other direction.

  • The two conclusions cannot be separated. Proving only the runSeq equality leaves no way to re-establish the hypothesis for the next step, and move 3 needs the footprint fact at the same inductive depth at which it is proving the value fact.

WellFormed survives every step, so the invariant holds along every path

theorem WellFormed_preserved {τ : Type} (P : ParM τ) : ∀ σ, WellFormed P σ → ∀ P3 σ3, Conf.run P3 σ3 ∈ stepC (Conf.run P σ) → WellFormed P3 σ3 := WellFormed_preserved_all.1 Ptheorem runSeq_invariant_chain {τ : Type} (P : ParM τ) (σ : State) (hwf : WellFormed P σ) (C : Conf τ) (h : Reaches (.run P σ) C) : ∀ P' σ', C = .run P' σ' → WellFormed P' σ' ∧ runSeq P' σ' = runSeq P σ := byτ:TypeP:ParM τσ:Statehwf:WellFormed P σC:Conf τh:Reaches (Conf.run P σ) C⊢ ∀ (P' : ParM τ) (σ' : State), C = Conf.run P' σ' → WellFormed P' σ' ∧ runSeq P' σ' = runSeq P σ

This resolves what looks like a circularity. WellFormed is defined by measuring footprints along runSeq — a solo, left-first run — while the conclusion is about interleavings, where no such order exists. Chaining says the hypothesis is nonetheless available at every configuration of every schedule, because footprints only shrink as a program steps and independence is monotone under shrinking either side.

Safety is three lines; liveness exhibits one schedule

→   apply chaining to the run, at P′ := pure rrunSeq (pure r) σ′ = runSeq p σ, and the left side is (r, σ′) by definition — so (r, σ′) = runSeq p σ
←   build the left-to-right schedulerun child 1 to completion — which is this theorem one level down — then child 2, then step through the join into the continuation

  • The forward direction uses no induction on the program at all: the induction already happened, inside conservation and chaining. That is the payoff of finding the right invariant.

  • The backward direction is a construction, and the one thing that could go wrong is tripping the race test. no_race_of_indep rules that out — which is where Bernstein's third clause is spent.

  • The children-level motive is "you can run every child to completion, left to right". It is mutual with the main statement because running one child to completion is the main statement, one level down.

Drop the hypothesis and the conclusion is false

p = write 5 1 q′ = read 5 (λv. write 8 v)q′ reads the cell p writes · W₁ ∩ R₂ = {5}, so C2 fails
→two schedules

  • Two different terminal heaps from one configuration, so wellFormed_canonical's conclusion is false here — and WellFormed is exactly what fails. The hypothesis is load-bearing, in Lean, on a program we exhibit.

  • A second counterexample fails differently: a loop-carried dependence A[i] := A[i-1] + 1 has an obligation that is unprovable rather than refuted, and it is kept as a test for that reason.

  • Examples/Races/ holds both, and property tests check both directions — equality on random independent programs, wrong on random racy ones.

  • This is the configuration the whole data-race literature is about — a store on one core, a load of the same cell on another. Our own pass can never build it, because a RAW edge puts the two statements in one thread; when the user writes it, wfB is the checker, and rejects.

  • The rejection is not a message but an execution: phase 1 names the conflicting cells by one walk of the tree, phase 2 searches for a schedule aimed at exactly those cells, and follow_sound turns what it finds into a Reaches … wrong proof.

  • So a wrong guess cannot produce a wrong claim — a bad guess merely finds nothing. Aiming is what makes it cheap: on three threads where the middle one is innocent, blind search takes 2.7 s and the aimed search 2 ms.

Automatic parallelization: one scoreboard pass, then a plan in program order

  • Bernstein's three clauses are the three kinds of dependence edge, found in one pass over the statements rather than by an O(n²) pairwise scan.

  • The unit is not a statement but a register-closed segment: a fork hands the continuation the pre-fork register file, so a register written inside a thread is gone at the join — both readings agree, so wfB cannot see it, and a load with the store consuming it is never split.

  • Nothing is reordered. The plan's threads are a consecutive partition of the units, so planUnits (plan us) = us is structural and the soundness proof needs no commutation argument.

  • The DAG's longest path is a lower bound on the depth of any schedule, so it is what decides whether a plan is optimal rather than merely better.

MLIR: one reader, and every language that targets it

  • N languages against one converter instead of one front end per language, and stage 1 is replaceable, so a hand-written .mlir feeds the same interface.

  • Generic form, not each dialect's assembly — --mlir-print-op-generic prints every op the same way, so one reader covers affine, memref, arith and func.

  • Not LLVM IR: unstructured br and phi nodes have no encoding in an inductive ParM, and a loop structurizer destroys the affine maps the lowering depends on.

  • MLIR.lower is a Lean function, so the translation is an object we can state a theorem about rather than a script to trust.

  • What is refused is refused loudly: a memory space, a dynamic dimension or a multi-block region gets a coded diagnostic with a position, never a silent approximation.

Limits

  • Registers cannot be renamed away — yet. noRegFlow is on raw read sets, stronger than the liveness atoms establishes, so a chain reusing %0 is declined and returned sequential.

  • Memory cannot be renamed at all. A Loc is reached by a computed address, so the cell is the name — privatization, the commonest OpenMP clause, is out of reach.

  • Footprints over-approximate. A[B[i]] reports the whole array and whileAtMost reports the branch union: conservative, never unsound, and the two-part verdict says which heaps the refusal covers.

  • ParM is inductive, so while true is unrepresentable; and whether order preservation itself costs depth is open.

Conclusions

  • Nine lines. A heap is a function; a program is a tree; runSeq reads it left to right; footprints are measured along that run; Indep is Bernstein; wfB asks it at every fork; a step moves one child, joins, or goes to wrong; runSeq is conserved by every step, so one outcome is reachable and reached; a fork and its sequence have the same runSeq.

  • One theorem, then arithmetic. wfB s = true ⇒ execPar s ∥≡ execSeq s, every schedule, arbitrary programs, kernel-checked — so each program pays decide, not a proof about interleavings.

  • The one hard case. A child that is not the leftmost takes a step, so the machine's heap and the reference heap disagree, and independence is what makes the disagreement invisible. Everything else is runSeq's own defining equation, read in the other direction.
