  • One shared cell turns the agreement into a refutation, in Lean.

One shared cell

parallel { [5] := 1 } | { [5] := 2 }one character: both write cell 5
/-- **The conclusion of `par_seq_eq` is false here.** One side terminates, the other cannot. -/ theorem not_parSeqEq (σ : State) : ¬ ParSeqEq (ParM.parPair wA wB) (ParM.seqPair wA wB) σ := fun h => par_no_outcome σ _ _ ((h _ _).mpr (seq_reaches σ))

  • The hypothesis of the main theorem is load-bearing: dropped, the conclusion is refutable in Lean.

  • Enumerating schedules is not a method. Two arms of n statements each already admit (2n)! / (n!)² interleavings; at n = 10 that is 184 756.

2 · Independence

  • Bernstein's three clauses, computed from the program text.

  • Why a separating conjunction is the wrong relation for this.

  • The iris-lean spike, and why no separation-logic library is used.

Bernstein's three clauses, computed from the program text

def Indep (f₁ f₂ : Footprint) : Prop := Disjoint f₁.writes f₂.writes ∧ Disjoint f₁.writes f₂.reads ∧ Disjoint f₂.writes f₁.reads

A footprint is two lists of cells, reads and writes, read off the syntax. Independence is a decidable Bool over them: three list intersections, no reasoning about interleavings.

Separating conjunction, and Bernstein

P ∗ Q asserts the two sides own disjoint heap fragments, so it cannot describe two threads reading one cell. No separation-logic library is used; framing is plain ∧ over footprints.

Why no separation-logic library

iris-lean, added as a dependency to answer one questioncan Indep be an instance of a bunched-implications ∗?
the BI instance costs nothingnon-step-indexed, ▷ := id, a discrete COFE · the step-indexing risk never arrived
its ∗ is exclusive separationthe state splits into disjoint-domain pieces, so a shared read is not expressible
its carrier is a partial mapCore.State is total · a restriction or an embedding before a triple can be stated

The dependency was removed once it had answered. Logic/Rules.lean frames with ∧ over footprints instead, and the parallel rule it proves is therefore fully general — shared reads included. What would supply read-sharing inside a ∗ is a fractional-permission ∗ over Core.State, and nothing available builds one off the shelf.

3 · The language and the theorem

  • ParM, and why par has to be our own constructor.

  • The surface language, and the verdict the checker prints.

  • wfB s = true → ParSeqEq (execPar s) (execSeq s).

par as our own constructor

inductive ParM : Type → Type 1 where | pure {α : Type} : α → ParM α | read {α : Type} : Loc → (Val → ParM α) → ParM α | write {α : Type} : Loc → Val → (Unit → ParM α) → ParM α /-- Fork every child at once, then continue with all their results. The only constructor whose meaning Lean does not already fix: `run` interprets it by interleaving, which is what makes the sequentialization theorem non-vacuous. -/ | par {β : Type} {αs : List Type} : Childs ParM αs → (Results αs → ParM β) → ParM β
Lean's Task(Task.spawn f).get = f () holds by rfl — parallel and sequential are the same term, so there is nothing to prove
ParM.para program is data; its meaning is fixed by step, which interleaves. Task is a compilation target only

ParM is inductive, so every program terminates: while true is unrepresentable, and that boundary is fixed by Lean having no coinductive types.

The surface language, and the verdict the checker prints

  • [l] is a cell, [A, e] a computed cell, %n a register. if, while … in, synchronize and print are the control constructs; every one has a Lean form.

  • Two interpreters, execPar and execSeq, read the same ParProg tree. The verdict is two-part: this heap by exact search, any heap by the syntactic check.

The theorem

wfB s = truedecided by decide: list intersections on footprints
→
every schedule of s ends where execSeq s endsstated as an iff on reachable outcomes

Every program below discharges its obligation by decide or by a size-free kernel lemma. No program carries a proof about interleavings of its own.

4 · Why it holds

  • A well-formed program has exactly one reachable outcome.

  • A race has no outcome at all, which is what excludes it.

Canonical outcomes

theorem wellFormed_canonical {τ : Type} (p : ParM τ) : ∀ σ r σ', WellFormed p σ → (Reaches (.run p σ) (.run (.pure r) σ') ↔ (r, σ') = runSeq p σ) := wellFormed_canonical_all.1 p

Read as an iff: → says no schedule terminates anywhere else, ← says that outcome is reached. par_seq_eq is this theorem applied to both sides and the results compared.

Races, and wrong

excluded, not given a behaviour

  • run returns an Option, and wrong absorbs: once a step finds two conflicting accesses ready at one instant, nothing recovers.

  • This is why the atomic grain is irrelevant to the theorem. No result depends on how coarsely a write is implemented.

  • Summing an array — quantified over the chunk plan.

6 · Autoparallelization

  • A sequential program is a right-leaning spine of seq nodes.

  • Where the parallelism is: five units, four dependences.

  • The spine rebuilt as three forks, proved with no hypothesis.

The sequential spine

buf a[5] a[0] := 3 a[1] := 4 %0 := a[0] a[2] := %0 * %0 %1 := a[1] a[3] := %1 * %1 %2 := a[2] %3 := a[3] a[4] := %2 + %3chain.prl — ten lines, nine of them statements

ParProg.block [s₀, …, s₈] is seq s₀ (seq s₁ (…)), so the order the statements were written in is the tree's right spine. The pass first cuts that spine into five register-closed units — %0 := a[0] and a[2] := %0 * %0 may not be separated, because a register is thread-private — and one scoreboard pass reads every dependence off them: [[], [], [0], [1], [2, 3]].

The dependence DAG

A register is thread-private, so %0 := a[0] and a[2] := %0 * %0 may not be separated: the unit, not the statement, is what a thread is built from. One left-to-right scoreboard pass then reads every dependence off the units' footprints — [[], [], [0], [1], [2, 3]]. Four of the ten pairs carry one; u0, u1 share no cell, as do u2, u3. That is the whole of the parallelism this program has.

The parallel plan

example (ρ : Regs) (σ : State) : (runSeq (ParProg.execPar (rewrite p) ρ) σ).2 = (runSeq (ParProg.execSeq p ρ) σ).2 := rewrite_sound p ρ σ -- and because the rewrite stays well-formed, `par_seq_eq` lifts that from one schedule to all example (ρ : Regs) (σ : State) : ParSeqEq (ParProg.execPar (rewrite p) ρ) (ParProg.execSeq (rewrite p) ρ) σ := rewrite_parSeqEq p (byρ:Regsσ:State⊢ p.wfB = true decideAll goals completed! 🐙) ρ σ

rewrite checks its own gate and hands back the program unchanged when it fails, which is why rewrite_sound carries no hypothesis. Nothing is ever reordered, so no commutation lemma is needed.

7 · Finding races, and MLIR

  • What the checker returns when it refuses: the schedule that disagrees.

  • A whole MLIR module in, a whole paralever program out.

What a refusal returns

2:T1 write [9] ← 2 pending 2:T0 read [9] pending Parallel aborts at Step 2. Reason: T0, T1 access: {9}. Parallel: 9↦2, T0 reads 2 Sequential: 9↦2, T0 reads 0paralever race — a read-after-write race

  • The two heaps agree. The divergence is what T0 observes, which a heap comparison would miss.

  • A found schedule is replayed against the semantics and turned into a Reaches proof by follow_sound, so a counterexample is checked, never believed.

  • The search is two-phase: scan for conflicting sites, then aim the schedule search at them.

Cost and scale

theorem time_le {s : ParProg} (h : wfB s = true) (ρ : Regs) (σ : State) : time (execPar s ρ) σ ≤ time (execSeq s ρ) σ := time_execPar_le_all.1 s ρ σ h

Parallelism reorders memory operations and removes none, so work is identical and only time falls — from the same Bool. Rolling a nest makes the certificate a check on three subscript maps instead of on the iteration space: flat from 64 points to 10⁹, against 58× at the largest size both can be measured.

Every refusal above is a precision loss, never a soundness one: across 28 labelled kernels the false-acceptance cell is zero, and that is a build-failing gate.

What was built

  • One metatheorem — Bernstein independence at every fork implies equality of reachable outcomes under every schedule — proved once, over a program model where par is a constructor and races are absorbing.

  • Two front ends over it: a surface language with a checker, a prover and a race explainer, and an MLIR reader that answers on a compiler's own representation.

  • Programs discharge the obligation by decide on footprints, by a size-free kernel lemma, or by one certificate over subscript maps that is flat to 10⁹ iteration points.
