Problem Statement

Some definitions to know:

  • State — σ : Loc → Val, a total heap. A configuration is a program paired with a heap, (p, σ), or wrong, which is terminal and absorbing.

  • Step — (p, σ) → c' lists the successors of a configuration. A fork offers every ready child, so that list is the nondeterminism itself.

  • Interleaving — a finite chain c → c₁ → … → c'. Reaches c c' holds when one joins them.

  • seq p q — p to completion, then q: one chain, no choice. par p q — the fork, joined once every child is pure.

  • WellFormed p σ — at every fork in p, against the heap that fork actually sees, the children's footprints are pairwise independent, and each child is itself well-formed. Indep is the clause at one fork; WellFormed is the recursive condition the theorem takes.

p : ParM α    q : ParM β    σ : State      WellFormed (par p q) σ
∀ r σ'.   Reaches (par p q, σ) (pure r, σ')  ⇔  Reaches (seq p q, σ) (pure r, σ')
par_seq_eq — the conclusion is ParSeqEq (par p q) (seq p q) σ, unfolded

Independence and WellFormedness

  • Bernstein's condition of Independence

  • Notion of WellFormedness

Bernstein's condition of Independence

def Indep (f₁ f₂ : Footprint) : Prop := Disjoint f₁.writes f₂.writes ∧ Disjoint f₁.writes f₂.reads ∧ Disjoint f₂.writes f₁.reads

  • A footprint is two Lists of cells, reads(R(.)) and writes(W(.)). It is computed from the program.

  • Independence is a decidable Bool over them.

Wellformedness: Independence is checked at every fork

def WellFormed {τ : Type} : ParM τ → State → Prop | .pure _, _ => True | .read l k, σ => WellFormed (k (σ l)) σ | .write l v k, σ => WellFormed (k ()) (σ.update l v) | .par cs k, σ => let r := runChilds cs σ IndepAll (childFootprints cs σ) ∧ WellFormedChilds cs σ ∧ WellFormed (k r.1) r.2

  • p is well formed from heap σ if, at every fork reached while running p from σ, its children are pairwise independent, each child is well formed, and execution remains well formed after the fork joins.

  • Each child is checked against the heap the child before it left, not against σ. The threads are independent, so that is also the heap the parallel run reaches.

ParM Monad and par constructor

inductive ParM : Type → Type 1 where | pure {α : Type} : α → ParM α | read {α : Type} : Loc → (Val → ParM α) → ParM α | write {α : Type} : Loc → Val → (Unit → ParM α) → ParM α /-- Fork every child at once, then continue with all their results. The only constructor whose meaning Lean does not already fix: `run` interprets it by interleaving, which is what makes the sequentialization theorem non-vacuous. -/ | par {β : Type} {αs : List Type} : Childs ParM αs → (Results αs → ParM β) → ParM β

  • The program is a tree of ParM constructors. The tree is data we can inspect.

  • ParM is inductive, so every program terminates: while true is unrepresentable, and that boundary is fixed by Lean having no coinductive types.

  • Why not Lean's Task? (Task.spawn f).get = f () holds by rfl, so parallel and sequential would be the same term and the theorem vacuous. Task is a compilation target only.

Definitions

def step {α : Type} : ParM α → State → List (Conf α) | .pure _, _ => [] | .read l k, σ => [.run (k (σ l)) σ] | .write l v k, σ => [.run (k ()) (σ.update l v)] | .par cs k, σ => if racingAll (nextAccsChilds cs) then [.wrong] else match allPure cs with | some vs => [.run (k vs) σ] | none => (stepChilds cs σ).map fun r => match r with | some x => .run (.par x.1 k) x.2 | none => .wrong
inductive Childs (Node : Type → Type 1) : List Type → Type 1 where | nil : Childs Node [] | cons {α : Type} {αs : List Type} : Node α → Childs Node αs → Childs Node (α :: αs)
parPair p q = .par Π[ p q ] (fun r => .pure (r.1, r.2.1)) seqPair p q = bind p (fun a => bind q (fun b => .pure (a, b))) parAll ps = .par (childsOf ps) (fun x => .pure (resultsToList ps x)) seqAll [] = .pure [] seqAll (p :: ps) = bind (seqPair p (seqAll ps)) (fun r => .pure (r.1 :: r.2))parPair is parAll at two children, not the other way round

  • step returns a list: empty is terminal, a singleton is deterministic, and a fork returns one entry per ready child. That list is where every schedule comes from.

  • racingAll is checked before the children move, so a fork with two conflicting next actions goes to wrong and stays there.

Language Framework, and the verdict the checker prints

buf A[2, 3] = 1, 2, 3, 4, 5, 6 buf out[3] %k := 10 parallel { %s := 0 for j in 3 { %v := A[0, j] if %v > 2 { %s := %s + %v * %k } else { %s := %s + %v } } %k := 99 out[0] := %s } | { parallel { %a := A[1, 0] out[1] := %a } | { %b := A[1, 2] out[2] := %b * %k } } print out, %k
reads {A[0,0] … A[1,2]} writes {out[0], out[1], out[2]} threads 2 rounds 4 parallel, 8 sequential verdict every heap Proved: Yes out = [33, 4, 60] 10← 10, not 99

  • Buffers are shared and registers are not: out[i] := %s is what Indep measures, %s and %k are invisible to it.

  • Registers are firstprivate, at every depth. All four threads read %k = 10 — which is why out[2] is 60. Thread 0 sets %k := 99 and the join discards it.

  • if … else branches per cell; print is erased from both interpreters, and is a barrier the parallelizer may not cross.

Proof of Equivalence

  • The two sides are never compared to each other.

  • Each collapses to a point; the points are equal by computation.

  • ParSeqEq reduces to WellFormed, once and for all programs.

The successor list

def step {α : Type} : ParM α → State → List (Conf α) | .pure _, _ => [] | .read l k, σ => [.run (k (σ l)) σ] | .write l v k, σ => [.run (k ()) (σ.update l v)] | .par cs k, σ => if racingAll (nextAccsChilds cs) then [.wrong] else match allPure cs with | some vs => [.run (k vs) σ] | none => (stepChilds cs σ).map fun r => match r with | some x => .run (.par x.1 k) x.2 | none => .wrong
the list is the nondeterminismempty = terminal · one entry = no choice · a fork = one entry per ready child
stepChilds (p :: ps) σ = (step p σ).map … ++ (stepChilds ps σ).map …the head child moves, appended to every move the tail can make — that ++ is the fan-out

  • There is no scheduler in the development. A schedule is a path through these lists, and Reaches is the transitive closure of membership in them.

  • So quantifying over schedules is quantifying over ∈.

The invariant: any child, not the left one

theorem step_combined {τ : Type} (P : ParM τ) : ∀ σ, WellFormed P σ → ∀ P3 σ3, Conf.run P3 σ3 ∈ stepC (Conf.run P σ) → runSeq P3 σ3 = runSeq P σ ∧ (∀ F, FDisjoint F (accesses P σ) → FDisjoint F (accesses P3 σ3)) := step_combined_all.1 P
P3 is any member of the successor list, under ∀ — one statement per scheduler choicethe proof rcases on List.mem_append: head moved, 10 lines · tail moved, 45 lines and the hard case

  • Why the tail case commutes. Its step changed one cell in W₂. By C3 that cell is outside R₁, so the head reads the same values — accesses_runSeq_locality. By C1 it is outside W₁, so the head does not overwrite it — runSeq_frame.

  • Why it can be done again. The second conjunct: a step only shrinks a footprint, so the sibling is still independent of the residue, and the invariant chains.

The bridge

theorem wellFormed_canonical {τ : Type} (p : ParM τ) : ∀ σ r σ', WellFormed p σ → (Reaches (.run p σ) (.run (.pure r) σ') ↔ (r, σ') = runSeq p σ) := wellFormed_canonical_all.1 p
{ outcomes of p from σ }every terminating schedule, however the scheduler moved
=under WellFormed
{ runSeq p σ }one element

  • The invariant chained along a Reaches derivation, with WellFormed_preserved re-establishing the hypothesis at each link. runSeq is constant along the chain, and at the end it is (r, σ′).

  • Uniqueness is →; existence is ←, from no_race_of_indep. Without existence a racy program reaches nothing and would satisfy the theorem vacuously on both sides.

Four steps to ParSeqEq

1. WellFormed (par p q) σ → WellFormed (seq p q) σwellFormed_of_seqPair · seq has no fork, so the Indep conjunct is dropped
2. ⟨par p q, σ⟩ →* ⟨pure r, σ′⟩ ⇔ (r, σ′) = runSeq (par p q) σthe bridge, on the left — every left-hand schedule is eliminated here
3. ⟨seq p q, σ⟩ →* ⟨pure r, σ′⟩ ⇔ (r, σ′) = runSeq (seq p q) σthe bridge, on the right — available only because of 1
4. runSeq (par p q) σ = runSeq (seq p q) σrfl — free, and carrying none of the content
chain 2, 4, 3 — that is ParSeqEq

  • The theorem is not two left-to-right runs compared. That is step 4, and it is rfl. The work is in 2 and 3: each is wellFormed_canonical, a whole set of schedules collapsing to a point.

  • Nothing after step 1 mentioned p or q. So ParSeqEq reduces to WellFormed — proved once, for every program there will ever be.

Parallel Programs are Faster

theorem time_le {s : ParProg} (h : wfB s = true) (ρ : Regs) (σ : State) : time (execPar s ρ) σ ≤ time (execSeq s ρ) σ := time_execPar_le_all.1 s ρ σ h

  • time counts rounds: one round is every running thread taking one step. The same Bool that proves the two readings agree also orders their spans.

  • Parallelism reorders memory operations and removes none, so work is unchanged and only time falls. The inequality is not conditional on a machine, a scheduler or a core count.

Neural net

/-- **The theorem.** Under every schedule, the net with all its layers' threads running at once reaches exactly the outcomes it reaches run thread-by-thread. -/ theorem forward_par_seq_eq (ρ : Regs) (σ : State) : ParSeqEq (ParProg.execPar forward ρ) (ParProg.execSeq forward ρ) σ := ParProg.par_seq_eq (byρ:Regsσ:State⊢ forward.wfB = true decideAll goals completed! 🐙) ρ σ

The weights are shared reads, so (C2) and (C3) are free inside a layer. Between layers the composition is sequential, and wfB recurses into each arm.

Autoparallelization

  • A sequential program is a right-leaning spine of seq nodes.

  • Where the parallelism is: five units, four dependences.

  • The spine rebuilt as three forks, proved with no hypothesis.

The sequential spine

buf a[5] a[0] := 3 a[1] := 4 %0 := a[0] a[2] := %0 * %0 %1 := a[1] a[3] := %1 * %1 %2 := a[2] %3 := a[3] a[4] := %2 + %3chain.prl — ten lines, nine of them statements

ParProg.block [s₀, …, s₈] is seq s₀ (seq s₁ (…)), so the order the statements were written in is the tree's right spine. The pass first cuts that spine into five register-closed units — %0 := a[0] and a[2] := %0 * %0 may not be separated, because a register is thread-private — and one scoreboard pass reads every dependence off them: [[], [], [0], [1], [2, 3]].

The dependence DAG

A register is thread-private, so %0 := a[0] and a[2] := %0 * %0 may not be separated: the unit, not the statement, is what a thread is built from. One left-to-right scoreboard pass then reads every dependence off the units' footprints — [[], [], [0], [1], [2, 3]]. Four of the ten pairs carry one; u0, u1 share no cell, as do u2, u3. That is the whole of the parallelism this program has.

The parallel plan

example (ρ : Regs) (σ : State) : (runSeq (ParProg.execPar (rewrite p) ρ) σ).2 = (runSeq (ParProg.execSeq p ρ) σ).2 := rewrite_sound p ρ σ -- and because the rewrite stays well-formed, `par_seq_eq` lifts that from one schedule to all example (ρ : Regs) (σ : State) : ParSeqEq (ParProg.execPar (rewrite p) ρ) (ParProg.execSeq (rewrite p) ρ) σ := rewrite_parSeqEq p (byρ:Regsσ:State⊢ p.wfB = true decideAll goals completed! 🐙) ρ σ

rewrite checks its own gate and hands back the program unchanged when it fails, which is why rewrite_sound carries no hypothesis. Nothing is ever reordered, so no commutation lemma is needed.

How the schedule is found

findWrongFrom fuel p σ:                      -- phase 1
  sites ← raceSites p σ                      every par node failing Bernstein,
  if sites = [] then none                     measured along the canonical run
  else findWrongGuided (targetsOf sites) fuel (run p σ)

findWrongGuided targets fuel c:               -- phase 2
  if 0 then none
  if some successor of c is wrong then [its index]
  else let (keep, hold) = partition (successors of c)
         by "does this step move a thread PAST a flagged cell?"
       first i in keep ++ hold with
         findWrongGuided targets (fuel-1) c′ = some s  ⇒  i :: s

  • Phase 1 names the cells; phase 2 is depth-first over step's successor list, trying last any step that moves a thread past one of them — a reordering, so nothing becomes unfindable.

  • Whatever comes back is re-run by follow and turned into a Reaches proof by follow_sound, so the counterexample is checked rather than trusted.

Limitations

  • Non-terminating programs are unrepresentable.

    • ParM is an inductive type, so every program it can express terminates.

  • Locks and atomics are out of scope.

    • The semantics sends a race to wrong and leaves it there, which is what makes the atomic grain irrelevant; a lock would make it relevant again.

  • A computed address widens the footprint.

    • A[B[i]] has a subscript the text does not determine, so the syntactic footprint might claim all of A.

  • A solver's unsat is not a proof.

    • z3 and cvc5 are not the Lean kernel, and neither is a build dependency.

    • It is reported as discharged by the named solver. A sat is recomputed in Lean before it is believed.
